# GPU vs NPU — 다 되는 병렬 연산기 vs 신경망만 하는 저전력 전용기

## 한 줄 요약
**GPU**는 **무엇이든 병렬로 빠르게** 도는 범용 연산기(학습·추론 다 됨, 대신 수백 W), **NPU**는 **신경망 추론이라는 정해진 연산만** 극도로 적은 전력으로 도는 전용 가속기(보통 **1~3 W**). 비교 축이 "누가 더 빠른가"가 아니라 **"와트당 얼마나, 얼마나 오래"** 라는 게 핵심이다.

## 공통점 (왜 자주 비교되나)
- 둘 다 결국 **행렬 곱-누적(MAC)** 을 대량으로 돌리는 물건이다 — 신경망 연산의 90% 이상이 이것.
- 둘 다 **CPU가 조율하고 일을 넘겨주는** 가속기다(호스트-디바이스 구조) → [[GPU vs CPU]].
- 요즘 노트북·폰에는 **CPU·GPU·NPU가 한 칩(SoC)에** 다 들어 있고 메모리를 공유한다.

## 먼저 — "신경망 추론"이 대체 무슨 연산인가
NPU가 **추론 전용**이라는 말이 왜 그렇게 큰 제약인지 알려면, 추론이 어떤 계산인지부터 봐야 한다.

### 학습(training) vs 추론(inference)
| | **학습** | **추론** |
|---|---|---|
| 하는 일 | 정답과 비교해 **가중치를 고친다** | 가중치는 **고정**, 입력을 넣어 답만 낸다 |
| 계산 | 순전파 + **역전파** + 가중치 갱신 | **순전파(forward pass) 한 번** |
| 정밀도 | 높아야 함(작은 기울기를 누적) | **낮춰도 견딤**(INT8/INT4) |
| 메모리 | 활성값·옵티마이저 상태까지 보관 | 가중치 + 약간의 중간값 |
| 빈도 | 한 번, 며칠~몇 달 | **요청마다, 수십억 번** |

**NPU에는 역전파·가중치 갱신을 위한 회로가 아예 없다.** "추론 전용"은 기능을 잠가둔 게 아니라 **애초에 그 하드웨어가 없는 것**이다.

### 추론 = 행렬곱의 연쇄
층 하나가 하는 일은 결국 이것뿐이다.

```
y = 활성화함수( W · x + b )
        ↑ W, b = 학습 때 정해져 고정된 숫자판(가중치)
          x = 앞 층에서 넘어온 값
```

이미지 인식이든 [[LLM]]이든 이 계산을 층 수만큼 반복한다([[Transformer]]의 어텐션도 결국 행렬곱). 그래서 **"곱해서 더한다(MAC)"** 하나만 잘하는 하드웨어를 만들면 신경망 대부분을 커버할 수 있다 — **전용 가속기가 성립하는 이유**다.

여기에 결정적인 성질이 하나 더 있다: **데이터에 따라 실행 흐름이 갈리지 않는다.** 어떤 입력이 와도 같은 순서로 같은 모양의 행렬곱을 한다. 그래서 CPU가 공들이는 분기 예측·비순차 실행이 **전혀 필요 없고**, NPU처럼 **연산 순서를 하드웨어에 고정으로 새겨넣는(데이터플로우) 설계**가 가능해진다.

### 두 가지 병목 — 계산이 문제냐, 읽어오는 게 문제냐
같은 "추론"이라도 성격이 갈린다. 이게 TOPS 숫자가 배신하는 지점이다.

- **연산 병목(compute-bound)** — 이미지 분류·CNN, LLM의 **prefill**(프롬프트를 한꺼번에 처리하는 단계). 가중치 하나를 읽어 여러 번 쓰므로 **연산 능력(TOPS)이 그대로 성능**이 된다.
- **메모리 병목(memory-bound)** — LLM의 **decode**(토큰을 하나씩 뱉는 단계). **토큰 하나 만들 때마다 모델 가중치를 전부 한 번씩 읽어야** 하는데, 읽어온 값으로 하는 계산은 얼마 안 된다. 결국 **메모리 대역폭이 상한**이다.

```
이론상 최대 생성 속도 ≒ 메모리 대역폭 ÷ 모델 크기

7B 모델을 INT8로 = 약 7 GB
  노트북 LPDDR (~130 GB/s)  →  130 ÷ 7 ≒ 18 tok/s
  RTX 4090 GDDR6X (~1,000 GB/s) →  1,000 ÷ 7 ≒ 140 tok/s
```
실제로는 이 천장의 **30~80% 정도**만 나오지만, **비율은 그대로다.** NPU가 TOPS를 아무리 올려도 시스템 메모리를 공유하는 한 이 격차는 좁혀지지 않는다 — 아래 [[#⚠️ TOPS 숫자의 함정|TOPS의 함정]]이 여기서 나온다.

### 왜 정밀도를 낮춰도 되나 (양자화)
학습은 아주 작은 기울기를 계속 더해가는 과정이라 정밀도가 깎이면 학습이 무너진다. 반면 **추론은 이미 확정된 숫자로 한 번 계산하고 끝**이라 반올림 오차가 누적될 여지가 적다. 그래서 FP32 → INT8로 **가중치를 4배 줄여도** 정확도 손실이 작다.

- 게다가 양자화는 **연산만 빨라지는 게 아니라 읽을 바이트 수 자체를 줄인다** → 위의 메모리 병목까지 같이 완화된다. 온디바이스에서 양자화가 선택이 아니라 전제인 이유.

### 추론 성능은 무엇으로 재나
- **TTFT(첫 토큰까지 걸린 시간)** — prefill 성능. 체감 반응성.
- **처리량(tok/s, 초당 이미지 수)** — decode 성능.
- **배치(batch)** — 여러 요청을 묶어 가중치를 한 번 읽고 여러 명에게 쓰기. **서버가 GPU를 쓰는 진짜 이유**가 이것이다.
- 개인 기기는 **배치 = 1**(나 혼자 쓴다)이라 묶을 게 없다 → 대역폭 한계를 그대로 맞는다. **NPU는 배치 1·저전력에, GPU는 큰 배치·고처리량에** 맞춰진 물건이라는 결론이 여기서 나온다.

## 차이 (핵심)

### 🎮 GPU — 프로그래머블 범용 병렬
- **SIMT 수천 코어 + 초고대역폭 메모리(HBM/GDDR)**. 무엇을 시킬지는 커널을 짜서 결정한다 → [[CUDA]].
- **정밀도 폭이 넓다** — FP32/TF32·FP16·BF16·FP8·INT8까지. 그래서 **학습(training)과 파인튜닝이 가능**하다.
- **새 연산자·새 아키텍처가 나와도 즉시 돌릴 수 있다.** 연구·프로덕션 서빙이 GPU에 몰리는 이유.
- 대가는 **전력과 발열** — 데스크톱 GPU 200~600 W, 서버 가속기는 700 W 이상. 배터리 기기에서 상시 구동은 불가능.

### 🧠 NPU — 고정된 데이터 흐름, 낮은 정밀도, 저전력
- **시스톨릭 어레이(systolic array)** 구조 — MAC 유닛을 격자로 깔고 데이터를 **흘려보내며** 매 클럭 전부를 일하게 한다. 128×128 배열이면 128×128 행렬곱을 **128 사이클**에 끝낸다.
- **INT8·INT4 저정밀 고정**. FP32 곱셈기는 INT8 대비 트랜지스터가 ~100배, 전력이 ~16배 든다. 정확도를 조금 내주고 **전력을 크게 버는** 거래 → 모델을 **양자화(quantization)** 해서 올려야 한다.
- **데이터 이동을 줄이는 게 설계 목표**다. 연산보다 **메모리에서 값을 끌어오는 게 더 느리고 더 전기를 먹는다**(메모리 월). 그래서 가중치를 최대한 **온칩 SRAM**에 두고 격자 안에서 재사용한다.
- 결과적으로 **같은 칩의 GPU 대비 TOPS/W가 대략 5~10배**. 40~60 TOPS를 **2~3 W**로 유지한다.
- 대가는 **유연성** — 지원하지 않는 연산자가 하나 끼면 그 부분은 CPU/GPU로 떨어지고(fallback), 이득이 사라진다. **학습은 사실상 불가**, 추론 전용.

## 비교표

| 기준 | 🎮 GPU | 🧠 NPU |
|---|---|---|
| 정체 | 범용 병렬 연산기 | 신경망 **추론 전용** 가속기 |
| 구조 | SIMT 수천 코어 | **시스톨릭 어레이**(고정 데이터플로우) |
| 정밀도 | FP32~FP8, INT8 | 주로 **INT8 / INT4** |
| 학습(training) | ✅ 가능 | ❌ 사실상 불가 |
| 전력 | 수십~수백 W | **1~5 W** |
| 전력 효율 | 기준 | **TOPS/W 약 5~10배** |
| 메모리 | 전용 HBM/GDDR(초고대역폭) | 시스템 메모리 공유 + **온칩 SRAM** |
| 유연성 | 새 모델·새 연산자 즉시 | 지원 연산자 밖이면 fallback |
| 소프트웨어 | **CUDA라는 사실상 표준** | Core ML·Windows ML·QNN·OpenVINO·LiteRT로 **파편화** |
| 있는 곳 | 서버, 데스크톱, 게이밍 노트북 | 폰·노트북 SoC(거의 전부), 임베디드 |
| 전형적 일 | 학습, 대형 [[LLM]] 서빙, 렌더링 | 배경 흐림, 노이즈 제거, 자막, 얼굴·음성 인식 |

## ⚠️ TOPS 숫자의 함정
- **TOPS는 정밀도를 명시해야 의미가 있다.** 거의 항상 **INT8 기준**이고, 같은 칩도 INT4로 재면 숫자가 배로 뛴다. **정밀도가 다른 TOPS끼리는 비교 자체가 성립하지 않는다.**
- **TOPS는 이론상 최대 MAC 처리량**일 뿐이다. 앞의 [[#두 가지 병목 — 계산이 문제냐, 읽어오는 게 문제냐|메모리 병목]]대로 **[[LLM]] 생성 속도는 대역폭이 결정**하므로, NPU가 시스템 메모리(LPDDR)를 공유하는 한 HBM/GDDR을 단 GPU를 따라잡을 수 없다.
- 그래서 **2026년 현재 로컬 LLM은 여전히 외장 GPU가 압도적으로 빠르다.** "40 TOPS NPU가 있으니 로컬 LLM이 잘 돌겠지"는 틀린 기대다.

### 실제 칩 (2026 기준 대략치, 전부 INT8 TOPS)
- **Copilot+ PC 요건 = NPU 40 TOPS 이상** (Microsoft가 정한 하한선. 상한도 성능 보장도 아니다)
- Qualcomm **Snapdragon X** Hexagon **45**, **X2 Elite/Extreme 80**
- Intel **Lunar Lake(Core Ultra 200V) ~48**, **Panther Lake 50**
- AMD **Ryzen AI 300(XDNA 2) ~50**, **Ryzen AI 400 60**
- Apple **M4 Neural Engine 38**

## 언제 무엇을 쓰나

**NPU가 맞는 일**
- **상시·백그라운드로 도는 가벼운 추론** — 화상회의 배경 흐림, 마이크 노이즈 제거, 실시간 자막, 눈맞춤 보정. **몇 시간씩 켜져 있어야 하는데 배터리를 못 쓰는** 일.
- **기기 밖으로 데이터를 안 보내야 할 때** — 프라이버시·오프라인 → [[온디바이스]].
- **작고 양자화된 모델**(수백 MB~수 GB, INT8/INT4) → [[온디바이스 모델 배포]].
- 팬이 없거나 발열 여유가 없는 기기(폰·태블릿·얇은 노트북·임베디드).

**GPU가 맞는 일**
- **학습·파인튜닝 전부** → [[파인튜닝]].
- **큰 모델을 빠르게** 돌리기, 배치 처리, 다중 사용자 서빙 → [[vLLM]].
- **새 아키텍처·커스텀 연산자** — NPU 툴체인이 아직 지원하지 않는 것.
- 서버·워크스테이션처럼 **전력이 제약이 아닌 환경** → [[온프레미스]].

> 실무 감각: **"이 추론이 사용자를 기다리게 하는가, 아니면 뒤에서 계속 도는가"** 로 나누면 대체로 맞다. 기다리게 하는 무거운 일은 GPU(또는 클라우드), 계속 도는 가벼운 일은 NPU.

## 경계가 흐려지고 있다
- **Apple M5(2025년 10월)** — 16코어 Neural Engine을 유지하면서 **GPU의 각 코어에 Neural Accelerator를 넣었다**. Metal의 텐서 API로 직접 프로그래밍 가능하고, GPU 기반 AI 연산 최고 성능이 M4 대비 4배 이상. 즉 **"NPU냐 GPU냐"가 아니라 "둘 다 있고 워크로드별로 나눠 쓴다"** 로 가고 있다.
- 반대 방향도 있다 — **NPU가 데이터센터로** 올라온다. Qualcomm이 Hexagon NPU 기반 랙스케일 추론 시스템 **AI200/AI250**을 내놓은 것이 예 → [[04-뉴스/2026-07-21]].
- 정리하면 NPU는 GPU를 대체하는 물건이 아니라 **"저전력 세 번째 차선"** 이다. CPU·GPU·NPU가 각자 맡는 구조가 기본형.

## 자주 헷갈리는 것
- **NPU ≠ TPU** — TPU는 구글이 **데이터센터 학습·추론용**으로 만든 대형 ASIC, NPU는 보통 **기기 안 저전력 추론기**. 구조(시스톨릭 어레이)는 뿌리가 같지만 급이 다르다.
- **"AI PC"는 마케팅 용어다** — NPU가 달렸다는 뜻일 뿐, 어떤 모델이 잘 돈다는 보장이 아니다.
- **NPU가 있어도 앱이 안 쓰면 무용지물** — GPU의 CUDA 같은 단일 표준이 없어 벤더별 런타임에 맞춰 변환·양자화해야 한다. 이 파편화가 NPU 활용의 가장 큰 실무 장벽.

## 왜 중요한가
- **AI를 어디서 돌릴지**(클라우드 GPU / 기기 NPU)가 곧 비용·지연·프라이버시 설계다 → [[온프레미스 vs 온디바이스]].
- 기기 성능표의 **TOPS를 그대로 믿으면 용량 산정을 틀린다.** 정밀도와 메모리 대역폭까지 봐야 실제 처리량이 나온다.
- 노트북·폰 앱에 AI 기능을 넣을 때, **"NPU에 올릴 수 있는 크기·연산자인가"** 가 모델 선택의 실질적 제약이 된다.

> ✅ **웹 교차검증 완료** — NPU가 **MAC/시스톨릭 어레이 기반 INT8·INT4 전용 가속기**로 **1~5 W 수준에서 동작하며 같은 칩 GPU 대비 TOPS/W가 약 5~10배**(40~60 TOPS를 2~3 W로 유지)라는 점, **FP32 곱셈기가 INT8 대비 트랜지스터 ~100배·전력 ~16배**라는 저정밀 채택 이유, **데이터 이동(메모리 월)이 최대 병목이라 온칩 SRAM 재사용이 설계 목표**라는 점, **Copilot+ PC의 NPU 40 TOPS 하한**과 2026년 칩별 수치(Snapdragon X 45·X2 Elite 80, Lunar Lake ~48·Panther Lake 50, Ryzen AI 300 ~50·400 60, Apple M4 38), **TOPS가 정밀도 명시 없이는 비교 불가이고 로컬 LLM 속도는 메모리 대역폭이 좌우해 2026년에도 외장 RTX GPU가 앞선다**는 점, **Apple M5(2025년 10월)가 GPU 각 코어에 Neural Accelerator를 추가하고 16코어 Neural Engine을 유지하며 GPU AI 연산 최고 성능이 M4 대비 4배 이상**이라는 발표를 Apple 뉴스룸·Engadget·Microsoft/벤더 자료·NPU 아키텍처 해설(시스톨릭 어레이·TOPS/W) 등 복수 출처로 확인. 추가로 **LLM의 prefill은 연산 병목·decode는 메모리 대역폭 병목**이고 **이론상 최대 생성 속도 ≒ 메모리 대역폭 ÷ 모델 크기**(실측은 그 천장의 30~80% 수준)라는 루프라인 관점, 학습이 역전파·기울기 누적 때문에 높은 정밀도를 요구하는 반면 추론은 저정밀 양자화를 견디며 **양자화가 연산량과 읽을 바이트 수를 함께 줄여 메모리 병목까지 완화**한다는 점도 복수 해설·벤치마크 자료로 확인.

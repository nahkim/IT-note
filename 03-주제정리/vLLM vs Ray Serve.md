# vLLM vs Ray Serve — 엔진 vs 오케스트레이션

## 한 줄 요약
둘은 **경쟁이 아니라 층이 다르다.** **vLLM = 한 모델을 빠르게 돌리는 추론 '엔진'**, **Ray Serve = 여러 모델·요청을 클러스터에 걸쳐 배치·확장·연결하는 '오케스트레이션(서빙) 층'**. 실제로는 **Ray Serve 안에 vLLM을 끼워** 같이 쓴다. → [[AI 모델 서빙 프레임워크]]

## 각각의 용도 (핵심)

### 🔧 vLLM — "이 LLM 하나를 최대한 빠르고 싸게"
- **용도**: 단일 LLM의 **처리량·지연·GPU 메모리 효율**을 극한까지 끌어올리는 것. 토큰을 실제로 생성하는 **엔진**.
- **강점**: PagedAttention(KV 캐시를 OS 페이징처럼) + 연속 배칭 → 같은 GPU로 훨씬 많은 동시 요청. OpenAI 호환 API, 텐서/파이프라인 병렬, 양자화. → 상세는 [[vLLM]]
- **한 대의 서버(또는 멀티 GPU 한 모델)** 관점. "어떻게 하면 이 모델을 더 많이 태울까"에 집중.

### 🎛️ Ray Serve — "여러 모델·단계를 묶어 서비스로, 그리고 알아서 확장"
- **용도**: 여러 모델·전처리·후처리를 **하나의 추론 파이프라인으로 엮고**, 트래픽에 따라 **각각 독립 오토스케일**하며, **클러스터(여러 노드)에 분산** 서빙하는 것. Ray(분산 컴퓨팅 프레임워크) 기반.
- **강점**:
  - **모델 컴포지션 / 디플로이먼트 그래프** — 예: `임베딩 → 리랭커 → LLM`을 `DeploymentHandle`로 연결해 하나의 [[RAG]] 파이프라인으로. → [[마이크로서비스]]처럼 각 단계가 독립 배포·확장.
  - **모델별 독립 오토스케일**(0까지 축소 포함), 요청 큐 깊이 기반 확장.
  - **프레임워크 무관** — LLM만이 아니라 비전·추천 등 **아무 파이썬/ML 코드**나 서빙. [[FastAPI]]로 HTTP 인그레스.
  - **Ray Serve LLM** API로 **vLLM을 엔진 삼아** OpenAI 호환 서빙 + 고급 패턴(전문가 병렬 EP, prefill/decode 분리).
- **여러 모델·여러 노드** 관점. "어떻게 조립하고, 라우팅하고, 확장할까"에 집중.

## 비교표
| 기준 | **vLLM** | **Ray Serve** |
|---|---|---|
| 층 | 추론 **엔진** (아래) | **서빙/오케스트레이션** (위) |
| 한 문장 용도 | 단일 LLM을 빠르게·싸게 추론 | 여러 모델·단계를 묶고 확장·라우팅 |
| 다루는 범위 | 한 모델(멀티 GPU까지) | 여러 모델·여러 노드(클러스터) |
| 대상 | LLM 특화 | **프레임워크 무관**(LLM·비전·추천 등) |
| 대표 기능 | PagedAttention·연속 배칭·양자화 | 모델 컴포지션·독립 오토스케일·라우팅 |
| 스케일 축 | 한 모델의 처리량 ↑ | 파이프라인·노드 수평 확장 → [[수평 확장]] |
| 관계 | Ray Serve 안의 **엔진으로 탑재됨** | vLLM을 **품고** 운영 기능을 더함 |

```
        │                          │                  │

        │                    │   vLLM     │ ← 엔진    │

```

## 언제 무엇을
- **vLLM만으로 충분** — LLM **하나**를 띄우면 되고, 단순 오토스케일은 [[쿠버네티스]]/KServe에 맡길 때. 가장 흔한 출발점.
- **Ray Serve 추가** — ① 여러 모델을 **한 파이프라인**으로 엮어야(RAG의 임베딩+리랭커+LLM, [[AI 에이전트|에이전트]] 워크플로) ② 모델마다 **다르게 오토스케일** ③ 이미 **Ray 생태계**(Ray Data/Train/Tune)를 쓸 때 ④ 여러 노드에 **분산** 서빙.
- **대안 서빙 층** — 패키징~배포 워크플로 중심이면 [[BentoML]], K8s 선언적 운영이면 KServe. Ray Serve는 **파이썬 친화·모델 조합·클러스터 확장**이 강점.

# 애드혹 서명 vs 정식 서명 — "위조 안 됐다"만 증명할까, "누가 만들었나"까지 증명할까

## 한 줄 요약
코드 서명은 **① 무결성(빌드 후 변조 안 됨)** 과 **② 신원(누가 만들었나)** 두 가지를 증명한다. **애드혹 서명은 ①만**, **정식 서명은 ①+②를 신뢰할 수 있는 인증서로** 증명한다. 그래서 **애드혹은 내 기계에서 돌리기 위한 최소 절차**, **정식 서명은 남에게 배포하기 위한 유일한 길**이다.

## 먼저 — 코드 서명이 하는 두 가지 일
1. **무결성 봉인** — 실행 파일·리소스의 해시(`cdhash`)를 계산해 서명에 넣는다. 한 바이트라도 바뀌면 서명이 깨진다.
2. **신원 확인** — 그 해시에 **인증서로 전자서명**해서 "이걸 만든 건 나(=Apple/CA가 신원을 확인해준 개발자)"라고 붙인다.

**애드혹은 1번만 하고 2번을 생략한다.** 인증서 없이 해시만 계산해 붙이므로, "변조되지 않았다"는 말할 수 있어도 **"누가 만들었는지"는 아무도 모른다.** 이게 모든 차이의 출발점이다.

## 애드혹 서명 (ad-hoc signing)

```bash
codesign -s - MyApp.app      # 인증서 자리에 하이픈(-) = 애드혹
codesign -dv --verbose=4 MyApp.app
#   Signature=adhoc          ← 인증서 체인(Authority) 줄이 아예 없다
```

- **인증서 체인이 없다.** 정식 서명이면 `Authority=Developer ID Application: …` → `Developer ID CA` → `Apple Root CA`로 이어지는 줄이 나오는데, 애드혹은 이 줄이 통째로 없다.
- **Team ID가 없다.** 팀 식별자에 묶이는 기능(App Groups, 키체인 공유, iCloud, 푸시 등 프로비저닝이 필요한 entitlement)을 쓸 수 없다.
- **지정 요구사항(designated requirement)이 해시 그 자체**다. 빌드가 조금만 달라져도 다른 앱으로 취급된다 → "같은 앱의 업데이트"라는 연속성이 성립하지 않는다.
- **사실상 내 기계 전용.** 다른 맥으로 복사하면 다운로드 격리(quarantine)와 Gatekeeper에 걸려 실행되지 않는다.

### 그런데 왜 굳이 애드혹이라도 하나 — 애플 실리콘 때문
**Apple 실리콘(arm64)에서는 서명 없는 네이티브 코드가 아예 실행되지 않는다.** Big Sur/M1부터 강제된 규칙이고 사용자가 끌 수 없다. 그래서 툴체인들은 서명 인증서가 없어도 **링커가 자동으로 애드혹 서명을 붙인다.**

> 즉 애드혹은 "보안 등급이 낮은 서명"이 아니라 **"실행은 되게 해주는 최소 형식 요건"** 에 가깝다. [[Tauri]] 문서가 CI에서 최소한 애드혹이라도 하라고 권하는 이유도 같다 — 안 하면 만든 사람 기계에서조차 안 뜬다.

## 정식 서명 (Developer ID + 공증)

macOS 기준으로 "정식"은 **인증서 서명 하나로 끝나지 않고 3단 세트**다.

```
1. 서명(sign)        Developer ID Application 인증서 (유료 개발자 프로그램 필요)
                     + Hardened Runtime + 필요한 entitlement 선언
2. 공증(notarize)    빌드를 Apple 서버에 올려 악성코드 스캔 → 통과 티켓 발급
3. 스테이플(staple)  발급된 티켓을 앱/디스크이미지에 박아 넣기
                     → 사용자가 오프라인이어도 검증 통과
```

- **공증은 심사가 아니다.** App Store 리뷰처럼 사람이 보는 게 아니라 **자동 악성코드 검사**다. 보통 수 분.
- 이 셋을 마쳐야 **Gatekeeper가 경고 없이 통과**시킨다. 서명만 하고 공증을 빼먹으면 다운로드한 사용자에게 여전히 차단 화면이 뜬다.
- App Store로 낼 거라면 Developer ID 대신 **Apple Distribution 인증서 + App Store Connect** 경로(공증은 스토어가 처리).

## 비교표

| | **애드혹 서명** | **정식 서명 (Developer ID + 공증)** |
|---|---|---|
| 명령 | `codesign -s -` | `codesign -s "Developer ID Application: …"` + `notarytool` |
| 증명하는 것 | **무결성만** | 무결성 + **개발자 신원** |
| 인증서 체인 | ❌ 없음 | ✅ Apple Root까지 이어짐 |
| Team ID | ❌ 없음 | ✅ 있음 |
| 비용 | **0원** | Apple Developer Program **연 $99** |
| Gatekeeper(다운로드한 앱) | ❌ 차단 | ✅ 통과 |
| 다른 사람에게 배포 | ❌ 불가(사용자 수동 우회 필요) | ✅ 가능 |
| 프로비저닝 필요한 entitlement | ❌ 못 씀 | ✅ 씀 |
| 자동 업데이트 연속성 | ❌ 빌드마다 별개 신원 | ✅ 같은 팀·같은 앱으로 인식 |
| 인증서 만료/폐기 | 해당 없음 | 만료 관리 필요, 악용 시 **폐기(revoke)** 가능 |
| 전형적 용도 | 로컬 개발·CI 스모크 테스트 | **실제 배포 전부** |

### ⚠️ "사용자가 우회하면 되지 않나"는 이제 통하지 않는다
예전엔 우클릭 → **열기**로 Gatekeeper를 넘길 수 있었지만, **macOS 15 Sequoia부터 이 우클릭 우회가 제거**됐다. 이제 사용자가 **시스템 설정 → 개인정보 보호 및 보안**까지 들어가 "확인 없이 열기"를 눌러야 한다. **비개발자에게 이 과정을 안내하는 건 사실상 배포 실패**다 — 애드혹으로 배포하지 말라는 뜻.

## 언제 무엇을 쓰나

**애드혹으로 충분한 경우**
- **내 기계에서 개발·디버깅** — 특히 Apple 실리콘에서 실행만 되면 되는 상황.
- **CI에서 빌드가 깨지지 않는지만 확인**하는 스모크 테스트(설치본 산출물은 버림).
- 사내에서 **[[MDM]] 없이 소수의 개발자에게** 전달 + 받는 쪽이 `xattr -d com.apple.quarantine`을 아는 경우(권장하진 않음).
- 오픈소스 프로젝트가 **인증서 없이 "일단 돌아가는" 바이너리**를 내놓을 때(README에 우회 안내 필수 — 지원 부담이 그대로 돌아온다).

**정식 서명이 필수인 경우**
- **불특정 사용자에게 배포하는 모든 경우** — 웹 다운로드, Homebrew Cask, 자동 업데이터.
- **자동 업데이트를 붙일 때** — 업데이터는 "같은 서명 주체"를 확인해 교체하므로 애드혹으로는 성립하지 않는다 → [[릴리즈]].
- **엔터프라이즈/보안 심사** 대상 — 서명 주체 확인이 통제 항목에 들어간다 → [[ISMS]].
- 카메라·마이크·화면 녹화 등 **TCC 권한을 쓰는 앱** — 권한 부여가 서명 신원에 묶여, 신원이 바뀌면 권한이 초기화된다.

> 실무 규칙: **개발 중에는 애드혹, 배포 브랜치·태그 빌드에는 정식 서명 + 공증.** [[CI-CD]]에서 인증서는 시크릿으로 주입하고, 태그 푸시에서만 공증 단계를 태우는 구성이 일반적이다 → [[Tauri 데스크톱 앱 빌드]].

## Windows는 좀 다르다 — 애드혹이 없다

| | macOS | Windows |
|---|---|---|
| 무서명 실행 | arm64는 **불가**(애드혹이라도 필요) | **가능**(대신 SmartScreen 경고) |
| "공짜 서명" | **애드혹** | **자체 서명(self-signed)** — 신뢰 저장소에 수동 등록해야만 의미 |
| 정식 | Developer ID + 공증 | **OV / EV 코드 서명 인증서**(CA 발급) |

- Windows는 서명이 없어도 실행은 되지만 **SmartScreen이 "알 수 없는 게시자" 경고**를 띄운다. 자체 서명 인증서는 사용자의 신뢰 저장소에 없으므로 **오히려 더 수상하게 보일 수 있다.**
- **2023년 6월부터** CA/Browser Forum 규정에 따라 OV·EV 가릴 것 없이 **개인키를 HSM·FIPS 하드웨어 토큰에 보관**해야 한다 → CI에서 쓰려면 클라우드 서명 서비스가 필요해졌다(예전처럼 `.pfx` 파일을 시크릿에 넣는 방식이 막혔다).
- **2024년 3월 이후 EV라고 즉시 경고가 사라지지 않는다.** OV·EV 모두 **다운로드 실적으로 평판을 쌓는** 구조로 바뀌었다 — "EV 사면 끝"이 아니다.

## 자주 헷갈리는 것

- **애플의 "Ad Hoc"은 두 가지 뜻이다.**
  - **macOS 애드혹 *서명*** — 이 노트의 주제. 인증서 없는 서명.
  - **iOS Ad Hoc *배포*** — 정반대다. **정식 배포 인증서로 서명**하되, 프로비저닝 프로파일에 **등록된 기기(연 100대 한도)** 에서만 설치되게 제한하는 **배포 방식**. 이름만 같고 성격이 다르다.
- **서명 ≠ 안전** — 서명은 "이 코드가 누구 것이고 변조되지 않았다"만 말한다. 서명된 악성코드도 존재한다(그래서 인증서 **폐기**와 공증 스캔이 함께 있는 것).
- **서명 ≠ 암호화** — 코드는 그대로 읽힌다. 봉인이지 금고가 아니다 → [[암호화와 해싱]].
- **공증(notarization) ≠ 심사(review)** — 자동 스캔이지 App Store 리뷰가 아니다.

## 왜 중요한가
- 데스크톱 앱을 처음 배포할 때 **"내 맥에선 되는데 받는 사람은 '손상되었습니다'가 뜬다"** 의 원인 대부분이 여기다. 빌드 문제가 아니라 **서명·공증 누락**이다.
- **비용과 시점의 문제**로 바꿔 생각하면 쉽다 — 애드혹은 공짜·즉시, 정식은 연 $99 + 인증서 발급·갱신·CI 시크릿 관리라는 **운영 부담**이 붙는다. 배포 계획이 있다면 **이 부담을 프로젝트 초기에 일정에 넣어야** 한다.
- 서명 주체는 **앱의 정체성**이다 — 권한(TCC)·자동 업데이트·키체인이 전부 여기에 묶이므로, 나중에 신원을 바꾸면 사용자 쪽 상태가 초기화된다.

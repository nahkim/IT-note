# 온콜 (On-call)

**한 줄 뜻**: 정해진 기간 동안 **장애 호출을 받기로 되어 있는 당번**. 알람이 울리면 새벽에도 일어나 1차 대응을 한다.

**부연**:
- 실무 골격: **로테이션**(주 단위 교대) + **에스컬레이션 정책**(1차가 n분 내 응답 없으면 2차로) + **인수인계**([[핸드오버]]). 누가 당번인지 모호하면 아무도 안 받는다 → [[R&R]]의 가장 날카로운 사례.
- 온콜의 품질은 **알람의 품질**과 같다. 사람이 손쓸 수 없는 알람, 자동 복구되는 알람은 꺼야 한다 — 안 그러면 [[알람 피로]]로 진짜 장애를 놓친다.
- 문화적 원칙 — **"만든 사람이 운영한다(you build it, you run it)."** 개발자가 자기 코드의 새벽 알람을 받으면 관측성과 안정성에 저절로 투자하게 된다.
- 당번을 사람이 아니라 **문서로 받쳐야** 한다: [[런북]]이 없으면 매번 가장 오래 다닌 사람에게 전화가 간다.

**관련**: [[런북]] · [[알람 피로]] · [[포스트모템]] · [[핸드오버]] · [[관제]] · [[성능 SLA]]

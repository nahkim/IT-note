# 사이드 이펙트 (Side Effect)

**한 줄 뜻**: 함수가 **결과값을 돌려주는 것 말고 바깥 세상을 건드리는 모든 일** — 전역 상태 변경, 파일·DB 쓰기, 네트워크 호출, 로그, 화면 갱신.

**부연**:
- 한국어로 "부작용"이라 옮기면 나쁜 것처럼 들리지만 **원래는 가치중립**이다. 사이드 이펙트가 하나도 없는 프로그램은 아무 쓸모가 없다(출력조차 못 함). 문제는 **예상 못 한 곳에 숨어 있을 때**.
- 없는 함수를 **순수 함수**라 하고, 같은 입력이면 늘 같은 출력이라 테스트·캐싱·병렬화가 쉽다 → [[함수형 프로그래밍]]이 미는 방향.
- 실무 원칙: **계산과 효과를 섞지 않는다.** 값을 계산하는 부분과 저장/전송하는 부분을 나누면 테스트할 곳이 명확해진다.
- 회의에서 쓰이는 두 번째 용법도 있다 — **"이 수정의 사이드 이펙트는 없나요?"** = 의도치 않은 여파, 즉 [[회귀]] 위험을 묻는 말. 같은 단어지만 층위가 다르다.

> 참고 — 프로그래밍 언어론의 표준 개념. 국내 회의에서는 "의도치 않은 여파"의 뜻으로도 흔히 쓰인다.

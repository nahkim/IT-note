# 컨플릭트 (Merge Conflict)

**한 줄 뜻**: 두 브랜치가 **같은 파일의 같은 부분**을 서로 다르게 고쳐서, Git이 자동으로 합칠 수 없어 **사람에게 판단을 넘기는 상태**.

**부연**:
- Git은 라인 단위로 본다. 그래서 **다른 기능인데 같은 줄**을 건드리면 충돌하고, **같은 함수인데 다른 줄**이면 조용히 합쳐진다 — 후자가 더 위험하다(문법은 맞는데 의미가 깨지는 **시맨틱 충돌**).
- 표식 `<<<<<<< HEAD` / `=======` / `>>>>>>> branch` 사이에서 **한쪽을 고르는 게 아니라 옳은 코드를 새로 만드는 것**이 원칙. 습관적으로 "내 것 선택"하다가 남의 수정을 날리는 사고가 흔하다.
- 예방이 해결보다 싸다: **자주 머지/리베이스**해서 브랜치를 짧게 가져가기, 큰 포맷팅 변경은 따로 커밋하기, 파일을 기능 단위로 쪼개기.
- 해결 후에는 반드시 **빌드와 테스트를 다시** 돌린다. 충돌 해결은 새 코드를 쓴 것과 같다.

> 참고 — Git 표준 개념. 시맨틱 충돌은 자동 병합이 되지만 의미가 깨지는 경우를 가리키는 통용 표현.

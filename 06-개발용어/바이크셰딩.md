# 바이크셰딩 (Bikeshedding)

**한 줄 뜻**: 정작 중요한 결정은 그냥 넘어가고 **누구나 한마디 할 수 있는 사소한 것에 시간을 다 쓰는 현상**. "버튼 색깔 회의".

**부연**:
- 유래: **파킨슨의 사소함의 법칙**(C. N. Parkinson, 1957) — 원자력 발전소 건설안은 금방 승인하면서 **직원용 자전거 보관소** 지붕 재질을 두고는 몇 시간을 다툰다. 원자로는 아무도 모르지만 자전거 보관소는 **모두가 의견을 낼 수 있기 때문**.
- 소프트웨어 업계로 퍼진 건 1999년 **Poul-Henning Kamp**가 FreeBSD 메일링 리스트에 쓴 "A bike shed (any colour will do)" 글을 통해서다.
- 개발 현장의 자전거 보관소들: 변수명, 코드 포매팅, 탭 vs 스페이스, PR 템플릿 문구, 색상 코드.
- 처방은 **의견을 막는 게 아니라 자동화·규칙화**다 — 포매터([[코드 리뷰]]의 nit 대상 제거)와 컨벤션을 도구로 못 박으면 논쟁 자체가 사라진다. 그리고 결정권자를 미리 정해 둔다([[R&R]]).
- 시간을 쓸 가치가 있는 자리인지 판별하려면 **되돌리기 비용**을 본다. 되돌리기 쉬운 결정(색깔)은 빨리 정하고, 어려운 결정(DB 선택, API 계약)에 회의 시간을 쓴다.

# 리베이스와 스쿼시 (Rebase / Squash)

**한 줄 뜻**: **리베이스**는 내 커밋들을 다른 커밋 위로 **옮겨 붙여 히스토리를 한 줄로 펴는 것**, **스쿼시**는 여러 커밋을 **하나로 합치는 것**. 둘 다 *히스토리를 다시 쓰는* 작업이다.

**부연**:
- 머지와의 차이는 **기록의 모양**이다. 머지는 갈라졌다 합쳐진 실제 역사를 그대로 남기고(머지 커밋 생김), 리베이스는 처음부터 최신 위에서 작업한 것처럼 **직선으로** 만든다. 어느 쪽이 옳다기보다 팀 [[그라운드 룰]]로 정할 문제.
- **황금률: 남들이 이미 받아 간 브랜치는 리베이스하지 않는다.** 커밋 해시가 전부 바뀌어서 다른 사람의 히스토리와 어긋난다. 강제 푸시(`--force`)가 사고로 이어지는 지점이 여기 — 쓰더라도 `--force-with-lease`.
- **스쿼시 머지**는 PR의 지저분한 커밋 20개(`오타`, `다시`, `진짜 마지막`)를 **한 개의 의미 있는 커밋**으로 눌러 main에 넣는 방식. 히스토리가 읽기 쉬워지는 대신 중간 과정과 개별 되돌리기는 잃는다.
- 리베이스 중 충돌은 **커밋마다** 나올 수 있다. 그래서 [[컨플릭트]]가 여러 번 뜨면 당황하지 말 것(`--continue` / 포기는 `--abort`).

**관련**: [[컨플릭트]] · [[체리픽]] · [[Git]] · [[그라운드 룰]] · [[코드 리뷰]]

---
> 참고 — Git 표준 기능. "공개된 브랜치는 리베이스하지 말라"는 원칙은 git-scm 공식 문서(Rebase의 위험)에서 강조하는 규칙.

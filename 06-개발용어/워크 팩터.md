# 워크 팩터 (Work Factor)

**한 줄 뜻**: 암호를 깨는 데 드는 **계산량(공격 비용)**. 비밀번호 해싱에서는 이 비용을 **내가 원하는 만큼 올릴 수 있게 만든 강도 손잡이**(bcrypt의 `cost`)를 가리킨다.

**부연**:
- **두 갈래로 쓰인다.**
  - *암호학 일반* — 무차별 대입에 필요한 연산량. 키가 **1비트 늘면 2배**(AES-128 ≈ 2^128). "이 알고리즘 얼마나 튼튼한가"의 척도.
  - *비밀번호 해싱* — 알고리즘 파라미터 그 자체. bcrypt는 **반복 횟수 = 2^cost**라서 cost를 +1 할 때마다 해시 한 번이 **2배 느려진다**.
- **감 잡기**: cost 12 → 2^12 = 4096회, 최신 서버에서 해시 1회 ≈ **250ms**. cost 13이면 ≈ 500ms. OWASP 최소선은 **10 이상**, 현업 관행은 **12~14**. 목표 감각은 "로그인 한 번에 250ms 안팎".
- **고정값이 아니라 올려야 하는 값** — 하드웨어가 빨라지면 공격 비용은 저절로 떨어진다. 값을 나중에 올릴 수 있게 설계한 것이 bcrypt(1999, *future-adaptable*)의 핵심 아이디어. [[암호화와 해싱|Argon2id]]는 이걸 **시간·메모리·병렬성** 3개로 쪼개, 메모리를 강제로 먹여 GPU 공격까지 겨냥한다.
- **[[트레이드오프]]가 명확하다** — 사용자 체감 지연 ↔ 공격자 비용. 너무 높이면 로그인 API 자체가 부하 표면(DoS)이 되고, 너무 낮으면 유출 시 해시가 순식간에 털린다.
- 일반 [[암호화와 해싱|SHA-256]]에는 이 손잡이가 없다. 빠른 게 장점인 해시라 비밀번호 저장에 쓰면 안 되는 이유가 바로 이것.

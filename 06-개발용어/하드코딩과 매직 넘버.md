# 하드코딩과 매직 넘버

**한 줄 뜻**: **하드코딩**은 바뀔 수 있는 값을 코드 안에 직접 박아 넣는 것, **매직 넘버**는 그렇게 박힌 값 중에서도 **왜 그 숫자인지 아무도 모르는 것**.

**부연**:
- ```if (retries < 3)``` 의 `3`, `sleep(86400)`, URL·API 키·경로 문자열. 특히 **환경마다 달라지는 값**을 박으면 배포할 때마다 코드를 고쳐야 한다 → [[환경 변수]]나 설정으로 빼는 게 정석.
- 매직 넘버의 진짜 문제는 값이 아니라 **의도 상실**이다. `86400`보다 `SECONDS_PER_DAY`가 나은 이유는 짧아서가 아니라, 나중에 바꿔도 되는 값인지 아닌지를 알려주기 때문.
- **다 빼는 게 정답은 아니다.** 절대 안 변할 값(원주율, HTTP 200)까지 설정으로 만들면 그건 [[오버엔지니어링]]이다. 기준은 "이 값이 **다른 이유로 바뀔 수 있는가**".
- 보안 쪽에선 하드코딩된 비밀번호·토큰이 대표적 사고 원인이다. 저장소에 한 번 커밋되면 히스토리에 영원히 남는다([[API 토큰]] 관리, 비밀 값은 [[환경 변수]]·시크릿 매니저로).

# 📝 오디오 코덱과 컨테이너 (MP3 vs Opus, 그리고 "왜 맥에서 안 열리나")

## 한 줄 요약
> "코덱은 소리를 압축하는 **방식**, 컨테이너는 그걸 담는 **포장지**다. 그리고 데스크톱 앱에서 **인코딩은 내가 넣지만 디코딩(재생)은 OS가 한다** — 이 비대칭이 포맷 선택을 좌우한다."

## 핵심 내용

### 1. 코덱 ≠ 컨테이너
- **코덱(codec)** — 오디오를 압축/복원하는 알고리즘. MP3, AAC, Opus, Vorbis, FLAC.
- **컨테이너** — 압축된 데이터 + 메타데이터(길이·채널·챕터 등)를 담는 파일 포맷. `.ogg`, `.webm`, `.mp4`, `.caf`, `.wav`.
- 같은 코덱이 여러 컨테이너에 들어갈 수 있다. **Opus 코덱**은 `.ogg`, `.webm`, `.caf` 어디에나 담긴다.
- 그래서 "이 파일이 안 열린다"의 원인은 둘 중 하나다 — **코덱을 모르거나, 포장지를 못 뜯거나.** 실무에서 발목 잡는 건 대개 후자다.
- [[WAV]]는 특이하게 "무압축 [[PCM]]을 담는 컨테이너"다. 코덱이 사실상 없는(=압축 안 하는) 형태.

### 2. 무압축 vs 손실 압축 — 용량 감각
48kHz 모노 16bit, 1시간 녹음 1트랙 기준:

| 포맷 | 비트레이트 | 1시간 | 절감 |
| --- | --- | --- | --- |
| WAV (PCM 16bit) | 768 kbps | ~345 MB | — |
| MP3 64 kbps | 64 kbps | ~29 MB | 약 12배 |
| Opus 32 kbps | 32 kbps | ~14 MB | 약 24배 |

- 음성은 음악보다 정보량이 적어 **낮은 비트레이트로도 충분히 알아들을 수 있다.**
- STT([[STT 음성 인식]]) 관점에선 손실 압축이 거의 문제가 안 된다. Whisper 계열은 어차피 **16kHz로 리샘플링**해서 쓰기 때문에, 64kbps MP3의 고주파 손실은 인식률에 사실상 영향이 없다.

### 3. Opus가 기술적으론 더 낫다
- WebRTC·Discord·Zoom이 쓰는 **음성 특화 최신 코덱**. 같은 용량이면 MP3보다 음질이 확실히 좋다.
- 저지연이라 실시간 통화에 강하고, 라이선스도 BSD로 자유롭다(MP3의 LAME 인코더는 LGPL).
- **그런데도 실무에선 MP3를 고르는 경우가 많다.** 이유는 아래.

### 4. 핵심 함정 — 인코딩은 앱, 디코딩은 OS
[[Tauri]]·Electron 같은 데스크톱 앱에서 파일 재생은 보통 웹뷰의 `<audio>` 태그로 한다. 그런데 **Tauri는 브라우저를 번들하지 않고 OS가 제공하는 웹뷰를 빌려 쓴다.**

| OS | 웹뷰 | 엔진 | Opus 재생 |
| --- | --- | --- | --- |
| Windows | WebView2 | Chromium | ○ 완전 지원 |
| macOS 15.4+ | WKWebView | WebKit | ○ (Safari 18.4에서 Ogg 지원 추가) |
| macOS ~15.3 | WKWebView | WebKit/AVFoundation | ✗ (`.ogg` 컨테이너 미지원) |

- Apple 미디어 스택은 **오랫동안 Ogg 컨테이너를 지원하지 않았다.** Opus 코덱 자체는 알아듣지만 `.opus`/`.ogg`라는 포장지를 못 뜯었다 → 3번의 "코덱은 아는데 컨테이너를 모르는" 전형적 사례.
- **2025-03-31 Safari 18.4(macOS 15.4 Sequoia·iOS 18.4)에서 Ogg 컨테이너의 Opus·Vorbis 재생이 추가되며 이 격차가 닫혔다.** 단 재생 한정이고, `MediaRecorder`로 Ogg Opus를 **녹음**하는 건 Safari에서 여전히 불안정하다.
- 그 이전 macOS를 지원해야 한다면 컨테이너를 바꾸는 우회로가 있다 — **WebM+Opus는 macOS 12+**, **CAF+Opus는 2017년(High Sierra)부터** 재생된다. 다만 사용자 폴더에 `.caf` 같은 낯선 확장자가 쌓이고 다른 도구와의 호환은 더 나빠진다.
- **웹뷰에서 열리는 것과 Finder에서 열리는 건 별개다.** QuickTime은 지금도 단독 `.opus` 파일을 재생하지 못한다(CAF로 감싼 Opus만 가능). 사용자가 파일을 더블클릭하는 시나리오라면 이쪽이 진짜 제약이다.
- 배포 대상의 **최소 OS 버전이 곧 사용 가능한 포맷의 하한**이다. Tauri는 `minimumSystemVersion` 미설정 시 기본값이 macOS 10.13이라, 별도 지정을 안 했다면 Opus는 사실상 후보에서 빠진다.

> **여기가 결정적**: 인코더 라이브러리를 앱에 넣는 건 "쓰기"만 해결한다. "읽기"는 OS 몫이라 내가 손댈 수 없고, **사용자가 OS를 올려주기 전까지 기다리는 수밖에 없다.**

### 5. 그럼 인코딩은 뭐가 필요한가 (런타임 설치 X)
- Rust면 `mp3lame-encoder`(LAME 소스 vendored), Opus면 `audiopus`/`opus` 크레이트 — **빌드 시 앱 바이너리에 같이 컴파일**된다.
- 사용자 맥/윈도우에 **따로 깔 게 없다.** 이 점은 MP3든 Opus든 동일하다. 앱 용량은 수백 KB 늘어나는 정도.
- 대안인 ffmpeg 바이너리 번들은 수십 MB + 플랫폼별 관리가 생겨서 단순 변환엔 과하다.
- 웹뷰(프론트)에서 인코딩하는 건 불가. MediaRecorder/WebCodecs는 MP3 **인코딩**을 사실상 지원하지 않는다.

### 6. 실무 판단 정리
- 목적이 **용량 절감**이면 MP3 64kbps만으로도 이미 12배다. 24배로 늘리자고 "구형 맥에서 파일이 안 열림"을 감수할 이유가 약하다.
- 사용자가 **파일을 직접 열어보는 아카이브**라면 → MP3. 30년 된 기본 지원 포맷이라 웹뷰·Finder·탐색기 어디서나, OS 버전과 무관하게 열린다.
- **앱 안에서만 소비**되고 사용자가 파일을 직접 만질 일이 없다면 → Opus가 낫다. 단 최소 지원 OS가 macOS 15.4+ 이거나, WebM/CAF 컨테이너를 쓸 각오가 있어야 한다.
- 일반화하면: **포맷 선택은 "가장 낡은 재생 환경"이 결정한다.** 코덱의 기술적 우열이 아니라.
- 상용 외부 배포라면 LAME의 **LGPL 정적 링크 조건**을 한 번 확인할 것.

## 코드 / 예시
```
[녹음 중]  PCM → WAV로 append          ← 핫패스는 건드리지 않는다(크래시 내성 유지)
                    │
[정지 후]           ▼
             WAV 읽어서 MP3 인코딩 → 저장 폴더엔 .mp3만
                    │
                    └─ 인코딩 실패 시? → WAV 그대로 저장 (녹음은 절대 잃지 않는다)

코덱 ≠ 컨테이너 — 같은 소리, 포장지만 다름 (macOS 웹뷰 기준)
  Opus(코덱) ┬─ .ogg  → macOS 15.4+ 부터 ○ (그 이하 ✗)
             ├─ .webm → macOS 12+ ○
             └─ .caf  → macOS 10.13+ ○   ← 가장 오래 거슬러 올라감
  ※ 단, Finder/QuickTime 더블클릭은 .caf 외엔 여전히 ✗
```

## 기억할 문장 / 핵심 포인트
> "**코덱은 아는데 컨테이너를 모른다**" — 재생 실패의 절반은 코덱이 아니라 포장지 문제다.
> 데스크톱 앱에서 **인코딩은 내가 번들할 수 있어도 디코딩은 OS에 종속된다.** 포맷 선택은 이 비대칭에서 출발해야 한다.
> **포맷의 하한선은 최신 OS가 아니라 내가 지원해야 하는 가장 낡은 OS가 정한다.** "Safari 18.4부터 된다"는 곧 "그 이하는 안 된다"는 뜻이다.
> 압축은 **녹음 중이 아니라 정지 후에** — 실시간 핫패스에 인코더를 끼우면 크래시 내성을 잃는다([[오디오 녹음 파이프라인]]).

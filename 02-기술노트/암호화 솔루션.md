# 📝 암호화 솔루션 — 저장·전송·사용 중 데이터 지키기

## 한 줄 요약
실무 암호화는 데이터의 **세 가지 상태**(저장/전송/사용 중)마다 다른 솔루션을 쓴다. 그리고 진짜 어려운 건 알고리즘이 아니라 **키 관리**다. (암호화 자체 원리는 → [[암호화와 해싱]])

## 핵심 내용

### 1. 데이터의 3가지 상태 × 암호화
| 상태 | 위협 | 솔루션 | 예 |
|---|---|---|---|
| **저장 중(at rest)** | 디스크·백업 탈취 | 디스크/DB/스토리지 암호화(AES-256) | LUKS·BitLocker·FileVault, DB **TDE**, S3 SSE |
| **전송 중(in transit)** | 도청·중간자(MITM) | **TLS 1.3**·mTLS·VPN | HTTPS([[HTTP와 HTTPS]]), [[SSH 공개키 인증]] |
| **사용 중(in use)** | 메모리 덤프·내부자 | **기밀 컴퓨팅(TEE)** | Intel SGX/TDX·AMD SEV, 동형암호(연구) |
- **사용 중이 가장 어렵다** — 처리하려면 대개 복호화해야 하므로. **TEE**(하드웨어로 격리·암호화된 메모리·CPU 영역)나 동형암호로 해결.

### 2. 키 관리 — 진짜 어려운 부분
- **"암호 알고리즘은 공개돼 있고 안전하다. 뚫리는 건 대부분 키 관리."**
- **엔벨로프 암호화(envelope)** — 데이터는 **DEK**(데이터 키)로 암호화하고, 그 **DEK를 다시 KEK**(마스터 키)로 암호화한다. 마스터 키만 KMS/HSM이 지키면 됨 → 대량 데이터에 효율적, **키 회전이 쉬움**(KEK만 바꾸면 됨).
- **KMS**(AWS KMS·GCP KMS·Azure Key Vault) — 관리형 키 서비스. **HSM** — 키를 **하드웨어에 가둠**(FIPS 인증). **Vault**(HashiCorp) — 시크릿·키·동적 자격증명 관리.
- 원칙: **키 회전 자동화**, [[RBAC]]·최소권한, **감사 로깅**, 평문 키는 메모리에서 즉시 폐기. → **직접 구현하지 말고** KMS·검증된 라이브러리를 쓴다.

### 3. 솔루션 카테고리 (뭘 쓰나)
- **전송** — TLS(인증서·[[URL 구조|HTTPS]]), **Let's Encrypt**(무료 인증서·PKI), **mTLS**(서비스 간 상호 인증).
- **저장** — 디스크(LUKS/BitLocker/FileVault), DB **TDE**(앱 수정 없이 파일 레벨 암호화), 클라우드 스토리지 **SSE**(+고객 관리 키 CMK), **애플리케이션/필드 레벨 암호화**(민감 컬럼만).
- **시크릿 관리** — [[환경 변수]]에 평문 키·비번 금지 → Vault·클라우드 Secrets Manager. (→ [[웹사이트 보안]])
- **종단간(E2EE)** — 서버도 못 보게 **양 끝에서만** 복호화(Signal 프로토콜·보안 메신저).
- **사용 중** — 기밀 컴퓨팅(TEE)·동형암호.

### 4. 흔한 함정
- **TDE·디스크 암호화의 한계** — 물리 탈취엔 강하지만 **정상 경로 접근(앱·SQL 인젝션)엔 무력**(자동 복호화되므로). 민감 필드는 **앱 레벨 암호화** 병행.
- **키를 코드/리포에 커밋** — [[OWASP Top 10|A02 암호화 실패]]의 단골. 반드시 시크릿 관리로.
- 약한 알고리즘·평문 저장(OWASP A02/A04).

## 기억할 문장 / 핵심 포인트
> "**암호화보다 키 관리가 어렵다.**" 알고리즘이 아니라 **키 수명주기**(생성·보관·회전·폐기)를 설계하라.
> **저장=AES · 전송=TLS · 사용 중=TEE**, 대량은 **엔벨로프 암호화(DEK↔KEK)**.
> **직접 구현하지 마라** — KMS/HSM/검증된 라이브러리.

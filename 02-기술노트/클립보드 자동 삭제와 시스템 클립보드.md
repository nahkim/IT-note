# 📝 클립보드 자동 삭제와 시스템 클립보드

## 한 줄 요약
클립보드는 **복사한 앱의 것이 아니라 시스템 공용 버퍼**다. macOS는 `pboard` 데몬이, Windows는 커널 오브젝트가 들고 있으며 **같은 사용자로 실행되는 아무 앱이나 권한 없이 읽고 쓴다.** 비밀번호 관리자의 "60초 뒤 자동 삭제"가 가능한 것도, 반대로 **그것이 보장이 될 수 없는 것도** 같은 이유다.

## 핵심 내용

### 1. 클립보드의 실체 — 앱이 아니라 시스템이 소유한다
- ⌘C를 누르면 그 앱이 자기 메모리에 담는 게 아니라 **시스템 서비스에 써 넣는다.** 붙여넣기는 거기서 읽는 것.
- macOS: **`pboard`** 데몬(+ `pbs`)이 관리. AppKit의 `NSPasteboard.general`이 그 창구.
- Windows: `OpenClipboard` → `SetClipboardData`/`GetClipboardData`. 커널이 소유하는 전역 자원.
- 따라서 다른 앱이 복사한 값을 내 앱이 지우는 것은 **남의 앱을 건드리는 게 아니라 공용 버퍼를 조작하는 것**이다.

### 2. 접근에 권한이 필요 없다 ⚠️
- macOS는 화면 녹화·접근성·마이크는 **시스템 설정에서 명시적 허가**를 요구하지만 **클립보드는 아무것도 묻지 않는다.**
- iOS는 14부터 "OO이(가) 붙여넣었습니다" 배너가 뜨지만 **macOS에는 그런 알림도 없다.**
- 즉 **실행 중인 아무 앱이나 당신의 클립보드를 조용히 폴링할 수 있다.** 클립보드 매니저 앱들이 정확히 그렇게 동작한다(`changeCount`를 주기적으로 확인).
- **자동 삭제 기능이 특권으로 되는 게 아니다.** 애초에 아무나 접근 가능한 자원이라 가능한 것.

### 3. "60초 뒤 삭제"의 실제 로직
1. 복사할 때 **넣은 값의 사본과 만료 시각**을 함께 기록해둔다.
2. 주기적으로(예: 1초 틱) 만료됐는지 본다.
3. **지우기 직전에 현재 클립보드 내용이 내가 넣은 값과 같은지 확인한다.**
4. 다르면 **건드리지 않는다.**

3번이 핵심이다. 그 사이 사용자가 다른 것을 복사했다면 그건 **남의 데이터**이고, 타이머 하나 때문에 사용자가 방금 복사한 문서 조각을 날리면 그 도구는 신뢰를 잃는다.

### 4. 클립보드 히스토리 제외 — 두 OS의 강제력이 다르다
| | macOS | Windows |
|---|---|---|
| 수단 | 페이스트보드 항목에 `org.nspasteboard.ConcealedType` 타입을 함께 넣음 | `CanIncludeInClipboardHistory`, `CanUploadToCloudClipboard` 클립보드 포맷에 `0` 기록 |
| 강제력 | **없음 — 협조적 관례** | **OS가 강제** (Win+V 목록·클라우드 동기화에서 실제 제외) |
| 실패 방식 | 관례를 무시하는 매니저는 그냥 가져간다 | — |

- macOS 쪽은 `NSPasteboard`가 항목마다 **임의의 타입 문자열**을 담을 수 있다는 성질을 이용해, 빈 데이터로 그 타입을 하나 끼워넣는 **표시(flag)**다. 규격은 [nspasteboard.org](http://nspasteboard.org)의 커뮤니티 표준.
- **문서에 "보장이 아니다"라고 반드시 적어야 하는 항목.**

### 5. 한계 — 무엇을 보장할 수 없나
- **이미 복사해 간 값은 회수할 수 없다.** 클립보드 매니저가 60초 안에 읽어갔다면 끝이다.
- **앱이 종료되면 타이머도 죽는다.** 복사 후 10초 만에 앱을 끄면 값이 그대로 남는다 → 종료 훅에서도 지워야 한다.
- **Universal Clipboard**(macOS↔iOS)는 다른 기기로 이미 건너간다.
- 삭제 주기가 틱 간격에 묶이므로 실제 삭제는 60~61초 사이.

## 코드 / 예시

```rust
// Rust에서 접근하는 경로 — 특별한 게 아니라 Cocoa 앱과 같은 API다.
//
//   내 앱 (Rust)
//     └ arboard
//         └ objc2 / objc2-app-kit      ← Objective-C 런타임 메시지 전송
//             └ AppKit NSPasteboard
//                 └ pboard 데몬

// 쓰기 (민감 값 → 히스토리 제외 표시 포함)
#[cfg(target_os = "macos")]
{
    use arboard::SetExtApple;
    cb.set().exclude_from_history().text(secret)?;   // ConcealedType
}
#[cfg(target_os = "windows")]
{
    use arboard::SetExtWindows;
    cb.set()
        .exclude_from_history()    // CanIncludeInClipboardHistory
        .exclude_from_cloud()      // CanUploadToCloudClipboard
        .text(secret)?;
}
```

```rust
/// **지우기 직전에 내용을 확인한다.** 다르면 건드리지 않는다 —
/// 그 사이 사용자가 다른 것을 복사했다면 타인의 데이터를 지우는 셈이다.
fn erase_if_matches<B: ClipboardBackend>(b: &mut B, expected: &str)
    -> Result<bool, ClipboardError>
{
    match b.read()? {
        Some(current) if current.as_str() == expected => { b.erase()?; Ok(true) }
        _ => Ok(false),
    }
}
```

```rust
// 테스트를 위해 트레이트 뒤에 둔다. 실제 클립보드로 테스트하면
// (1) 개발자가 방금 복사한 것을 날리고 (2) 헤드리스 CI엔 클립보드가 없고
// (3) 병렬 테스트가 같은 자원을 놓고 경쟁해 무작위로 실패한다.
pub trait ClipboardBackend {
    fn write(&mut self, text: &str, sensitive: bool) -> Result<(), ClipboardError>;
    fn read(&mut self) -> Result<Option<Zeroizing<String>>, ClipboardError>;
    fn erase(&mut self) -> Result<(), ClipboardError>;
}
```

## 기억할 문장 / 핵심 포인트
> **클립보드는 복사한 앱의 것이 아니라 로그인 세션에 하나 있는 공유 버퍼다.**

> macOS는 클립보드 접근에 **권한을 묻지 않는다.** 화면 녹화는 묻고 클립보드는 안 묻는다.

> **자동 삭제는 노출 창을 좁히는 완화책이지 보장이 아니다.** 이미 읽어간 값은 회수할 수 없다.

> 지우기 전에 **내용이 내가 넣은 것과 같은지 반드시 확인한다.** 아니면 남의 데이터를 지운다.

> macOS의 히스토리 제외는 **OS 강제가 아니라 협조적 관례**다. Windows는 OS가 강제한다.

## 내 생각 / 적용할 점
- 비밀번호 관리자를 만든다면 **"60초 뒤 삭제"를 기능으로 광고하되 보장으로 쓰지 말 것.** 사용자 문서에 「클립보드 매니저가 이미 가져간 값은 회수 불가」를 명시해야 한다. 보장 범위를 부풀리면 사용자가 그걸 믿고 위험하게 행동한다.
- **`masked` 같은 분류 플래그의 UI 라벨은 "결과"로 붙이는 게 낫다.** 「가림」이라고 쓰면 화면 표시 토글과 구분이 안 되지만, 「비밀 · 복사 60초」라고 쓰면 무엇이 달라지는지 바로 읽힌다.
- **종료 훅에서도 클립보드를 지워야 한다.** 잠금만 처리하고 종료를 빠뜨리기 쉬운데, 사용자 입장에서 둘은 같은 행동이다.
- 클립보드를 다루는 코드는 **트레이트 뒤에 두고 가짜 백엔드로 테스트**한다. 실제 클립보드를 쓰는 테스트는 개발자의 클립보드를 파괴하고 CI에서 무작위로 실패한다.

# 🧩 pm2 (Node 프로세스 매니저)

> 🔒 경로·서비스명은 자리표시자다. `myproj`(프로젝트) · `admin-api`/`app-api`(서비스)

## 한 줄 요약
Node 앱은 그냥 띄우면 **터미널을 닫는 순간 죽고, 예외 하나에 영영 멈춘다.** pm2는 이 프로세스를 **대신 붙잡고 있어 주는 관리자**다 — 죽으면 재시작, 서버 재부팅하면 자동 기동, CPU 코어 수만큼 복제, 로그 모아주기. **핵심 함정은 하나: 환경변수를 기동 시점에만 읽는다.**

## 핵심 내용

### 1. 무엇을 대신 해주나

| 맨손 `node app.js` | pm2 |
|---|---|
| 터미널 닫으면 죽음 | 백그라운드 데몬으로 생존 |
| 예외로 죽으면 끝 | **자동 재시작** |
| 서버 재부팅하면 안 뜸 | `pm2 startup` + `pm2 save` 로 부팅 시 복구 |
| CPU 코어 1개만 사용 | **클러스터 모드**로 코어 수만큼 복제 |
| 로그는 알아서 | 프로세스별 `out`/`error` 로그 분리·회전 |
| 배포 중 다운타임 | `reload` 로 하나씩 교체(무중단) |

→ 리눅스 표준 방식인 [[systemd]] 로도 같은 일이 되지만, pm2는 **Node 전용 편의 기능**(클러스터·무중단 리로드·`pm2 ls`)이 붙어 있어 Node 진영에서 널리 쓰인다.

### 2. 기본 명령

```bash
pm2 start app.js --name admin-api        # 띄우기
pm2 ls                                    # 목록·상태·재시작 횟수·메모리
pm2 logs admin-api --lines 100            # 로그 (실시간)
pm2 restart admin-api                     # 죽였다 다시 (순간 끊김 O)
pm2 reload  admin-api                     # 하나씩 교체 (클러스터 모드에서 무중단)
pm2 describe admin-api                    # 이 프로세스가 실제로 쓰는 설정·env 확인
pm2 save && pm2 startup                   # 현재 목록을 부팅 시 자동 복구하도록 등록
```

> 💡 **`pm2 ls` 의 `↺`(restart 횟수)가 계속 늘고 있으면 앱이 죽고 되살아나기를 반복 중**이라는 뜻이다. "서비스는 되는데 느리다"의 흔한 범인.

### 3. ⚠️ 가장 큰 함정 — env는 **기동 시점에만** 읽힌다

```bash
vi /home/ec2-user/myproj/env/admin-api.env   # 값을 고쳤다
# …그런데 앱은 여전히 옛날 값으로 돈다
```

프로세스는 **시작할 때 받은 환경변수 복사본**을 들고 산다. 파일을 고쳐도 **이미 돌고 있는 프로세스에는 전달되지 않는다.** → [[환경 변수]] · [[프로세스와 스레드]]

게다가 pm2는 한 번 띄운 프로세스의 env를 **자기가 캐시**한다. 그래서 그냥 `restart` 해도 **옛 값으로 다시 뜨는** 경우가 있다.

```bash
pm2 restart admin-api --update-env    # ✅ 환경변수를 다시 읽어서 재시작
pm2 delete admin-api && pm2 start …   # 확실하게 하려면 지웠다 다시
pm2 describe admin-api | grep -A20 env  # 실제로 뭘 들고 있는지 확인
```

> 🔑 **"파일을 고쳤다"와 "앱이 그 값으로 돈다"는 다른 사건이다.** 고친 뒤 반드시 `--update-env` 재시작 + `describe` 확인.

### 4. 클러스터 모드 — 포트 하나에 프로세스 여럿

```bash
pm2 start app.js -i max --name app-api   # -i = instances, max = CPU 코어 수
```
- Node의 `cluster` 모듈을 써서 **같은 포트를 여러 프로세스가 공유**한다(커널이 분배).
- 이 모드에서만 `pm2 reload` 가 **무중단**이 된다 — 하나 죽이고 새로 띄우고, 다음 것 교체. → [[무중단 배포]]
- ⚠️ **상태를 메모리에 들고 있으면 깨진다.** 세션·캐시·인메모리 큐는 프로세스마다 따로 생긴다 → Redis 같은 외부 저장소로 빼야 한다. → [[수평 확장]]

### 5. 실전 — 한 서버에 여러 앱, 디렉터리 관례

작은 규모에서는 **서버 한 대에 서비스 여러 개**를 pm2로 같이 띄우는 구성이 흔하다. 포트로만 구분한다.

```
 EC2 한 대 (여러 대면 전부 동일 구성)
 ├─ admin-api   :3001     ← 관리자용 API
 ├─ app-api     :3000     ← 앱용 API
 └─ monitor     (포트 없음) ← 배치/모니터링. 외부에서 안 부름
```

디렉터리 관례도 거의 고정된 모양이 있다.

```
 /home/ec2-user/myproj/
 ├─ <서비스>/current     ← 배포된 코드 (릴리스 교체 지점)
 ├─ env/<서비스>.env     ← 환경변수. 🔒 저장소에 없다, 서버에서만 관리
 └─ logs/                ← pm2 로그
```

- **`current`** — 새 릴리스를 옆에 풀어두고 이 지점만 바꾸는 방식. 롤백이 "되돌리기" 한 번이 된다. → [[릴리즈]]
- **`env/`가 저장소에 없는 이유** — 환경(로컬/스테이지/운영)마다 값이 다르고 비밀값이 섞인다. 대신 **서버가 유일한 원본**이 되므로, 서버를 다시 만들 때 복구 절차가 필요하다.
- ⚠️ **서버가 여러 대면 env도 여러 벌이다.** 한 대만 고치면 로드밸런서가 돌리는 요청의 **일부만** 새 설정으로 동작하는 기묘한 상태가 된다. → [[로드 밸런서]]

**`ecosystem.config.js` 로 묶기** — 명령줄로 매번 띄우는 대신 파일로 선언한다.
```js
module.exports = {
  apps: [
    { name: 'admin-api', script: 'dist/main.js', cwd: '/home/ec2-user/myproj/admin-api/current',
      instances: 2, exec_mode: 'cluster', env_file: '/home/ec2-user/myproj/env/admin-api.env' },
  ],
}
```
→ `pm2 start ecosystem.config.js` 한 줄. 구성이 **코드로 남아** 서버 재구축 때 재현된다.

### 6. 점검 체크리스트

```bash
pm2 ls                        # 상태 online? 재시작 횟수 비정상적으로 높지 않나?
pm2 describe <앱> | grep -i "exec mode\|instances\|uptime\|script path"
pm2 logs <앱> --err --lines 50   # 에러만
ss -tlnp | grep -E ':(3000|3001)'  # 포트를 실제로 잡고 있나
pm2 flush                     # 로그 비우기 (디스크 찼을 때)
```

> ⚠️ **pm2 자체가 사라지는 경우** — `pm2 startup` 을 안 해두면 서버 재부팅 후 아무것도 안 뜬다. `pm2 save` 로 현재 목록을 저장해 두는 것까지가 한 세트다.

## 기억할 문장 / 핵심 포인트
> **env는 기동 시점에만 읽힌다.** 파일 수정 ≠ 반영. `pm2 restart --update-env` 까지 해야 끝.
> **`pm2 ls` 의 재시작 횟수는 건강검진표다.** 숫자가 늘고 있으면 앱이 계속 죽고 있는 것.
> **클러스터 모드의 전제는 "상태 없음"** — 메모리에 세션을 들면 프로세스마다 다른 세상이 된다.
> **`pm2 save` + `pm2 startup` 까지가 한 세트.** 안 하면 재부팅 한 번에 전부 사라진다.
> **서버가 여러 대면 env도 여러 벌** — 한 대만 고치면 절반만 맞는 상태가 된다.

## 내 생각 / 적용할 점
- 설정 바꾸고 "왜 안 먹지"로 시간 쓰기 전에 **`pm2 describe` 로 실제 들고 있는 값부터** 보기
- 명령줄 `pm2 start` 는 서버 재구축 때 재현이 안 된다 → **`ecosystem.config.js` 로 옮기기**
- 컨테이너(ECS/K8s)로 가면 재시작·복제·로그는 플랫폼이 하므로 **pm2는 오히려 이중 관리**가 된다. 컨테이너 안에서는 보통 pm2를 빼는 게 맞다
- `env/`가 서버에만 있는 구조는 **서버가 곧 원본**이라는 뜻 — 최소한 어딘가에 백업/문서가 있어야 한다

# DOM (Document Object Model, 문서 객체 모델)

## 한 줄 정의
브라우저가 HTML 문서를 읽어 만든 **트리 구조의 객체 모델** — JavaScript가 문서를 읽고 고칠 수 있게 해주는 **프로그래밍 인터페이스**.

## 자세히

### HTML ≠ DOM
- **HTML**은 서버가 보낸 **텍스트**. **DOM**은 브라우저가 그걸 파싱해 메모리에 세운 **객체 트리**.
- 그래서 둘은 달라질 수 있다: JS가 요소를 추가하면 DOM만 바뀌고(**"페이지 소스 보기"에는 안 보임**), 브라우저가 빠진 `<tbody>`를 자동 보정하기도 한다.
- **개발자 도구의 Elements 패널이 보여주는 것은 DOM**이지 원본 HTML이 아니다 → "소스에는 없는데 화면엔 있다"의 정체. ([[개발자 도구]])

### 구조
```
Document
└─ html
   ├─ head → title → "제목"(텍스트 노드)
   └─ body
      ├─ h1 → "안녕"
      └─ div#app → ...
```
- 노드 종류: **요소(Element)**, **텍스트**, **주석**, **속성** 등.
- 표준은 W3C/WHATWG가 정의하며, JS 언어 자체가 아니라 **브라우저가 제공하는 웹 API**다. (그래서 Node.js엔 기본적으로 DOM이 없다)

### 자주 쓰는 조작
```js
document.querySelector('#app');          // 선택
el.textContent = '안전한 텍스트';          // ✅ 텍스트 삽입 (XSS 안전)
el.innerHTML   = userInput;              // ⚠️ HTML 파싱 → DOM 기반 XSS 위험
el.classList.add('active');              // 클래스
el.addEventListener('click', fn);        // 이벤트
document.createElement('li');            // 생성
```
- **이벤트 전파**: 캡처링(위→아래) → 타깃 → **버블링(아래→위)**. 버블링을 이용해 부모에 하나만 리스너를 다는 **이벤트 위임**이 기본 기법.

### 왜 "DOM 조작은 느리다"고 하나
DOM 자체보다 **그 조작이 유발하는 레이아웃·페인트**가 비싸다. 특히 바꾸고 나서 바로 크기를 읽으면 **강제 동기 레이아웃**이 발생한다 → [[리플로우]].

- **가상 DOM(Virtual DOM)** — React 등이 쓰는 기법. 변경을 메모리상의 가벼운 트리에 먼저 반영하고 **차이(diff)만 실제 DOM에 적용**해 조작 횟수를 줄인다. "가상 DOM이 무조건 빠르다"기보다 **실수로 비싼 조작을 반복하지 않게 해주는 안전장치**에 가깝다. (Svelte·Solid는 컴파일 단계에서 직접 조작 코드를 생성하는 반대 노선)
- **Shadow DOM** — 컴포넌트 내부의 DOM·스타일을 **캡슐화**해 바깥과 충돌하지 않게 하는 웹 컴포넌트 표준.

## 왜 중요한가
- 프론트엔드가 다루는 **대상 그 자체**. 프레임워크가 감춰줘도 결국 밑에서는 DOM이 바뀐다.
- **DOM 기반 [[XSS]]**, 렌더링 성능([[리플로우]]), 접근성(시맨틱 태그·ARIA) — 실무 이슈 대부분이 DOM 이해에서 갈린다.

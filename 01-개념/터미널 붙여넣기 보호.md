# 터미널 붙여넣기 보호 (Bracketed Paste)

## 한 줄 정의
붙여넣은 텍스트에 섞인 **개행(`\n`) 하나가 곧바로 명령 실행이 되는 것**을 막기 위해, 터미널·셸이 "이건 타이핑이 아니라 붙여넣기"임을 구분해 처리하는 장치.

## 자세히

### 무엇이 위험한가 — 개행 = Enter
셸은 입력 버퍼에 개행이 들어오면 **그 줄을 실행**한다. 즉 복사한 내용 끝에 개행이 붙어 있으면 **Ctrl+V만으로, Enter를 누르지 않아도 실행**된다.

여기에 **페이스트재킹(pastejacking)** 이 얹힌다.
- 웹페이지는 `copy` 이벤트를 가로채 **클립보드 내용을 바꿔치기**할 수 있다(2016년 Dylan Ayrey의 데모로 널리 알려짐). CSS로 화면에 안 보이는 텍스트를 숨기는 고전적 수법도 있다.
- 결과적으로 **화면에 보이는 명령 ≠ 실제로 복사된 내용.** `brew install foo`처럼 보이는 블록을 긁었는데, 실제로는 개행 + 악성 명령이 딸려오는 식.
- JS 방식은 **한 글자만 복사해도** 전체 페이로드를 심을 수 있어 CSS 수법보다 강력하다.
- 문서·가이드·"기술지원" 페이지를 사칭한 사회공학과 결합될 때 특히 위험하다.

### 방어 1 — Bracketed Paste (셸·터미널 레벨, 조용히 동작)
터미널이 붙여넣기 구간을 **`ESC[200~` … `ESC[201~`** 로 감싸서 보내면, 셸은 그 구간을 **"실행할 명령"이 아니라 "그냥 문자열"** 로 취급한다.
- 개행은 **실행이 아니라 줄바꿈 문자로 삽입**된다 → 사용자가 직접 Enter를 눌러야 실행.
- 붙여넣은 텍스트가 **하이라이트**되어 눈에 띈다. 자동완성·히스토리 확장·에디터 자동 들여쓰기 같은 부작용도 함께 막힌다.
- **기본 활성 시점**: zsh는 **5.1**, bash는 **5.1(readline 8.1)** 부터 기본 ON. (지원 자체는 readline 7.0 / bash 4.4부터)

```zsh
echo $ZLE_BRACKETED_PASTE     # zsh: 값이 있으면 켜져 있음
unset zle_bracketed_paste     # zsh 끄기 (권장하지 않음)
# bash: ~/.inputrc 에  set enable-bracketed-paste off
```

> ⚠️ **한계**: bracketed paste는 "실행을 막는" 게 아니라 **"Enter를 사람이 누르게" 만드는** 장치다. 붙여넣은 내용을 읽지 않고 Enter를 치면 결과는 같다. 또 이를 지원하지 않는 낡은 터미널·셸, 원시 모드로 도는 프로그램에서는 적용되지 않는다.

### 방어 2 — 터미널 앱의 확인 다이얼로그 (iTerm2 등)
iTerm2의 **`Warn Before Multi-Line Paste`**(Edit → Paste Special). 뜨는 조건이 정해져 있어서 **매번 뜨지 않는다**:
- 붙여넣을 내용이 **여러 줄**일 때
- **한 줄이어도 끝에 개행이 붙어 있을** 때 (= 붙이자마자 실행되는 경우)
- Shell Integration을 설치했다면 **셸 프롬프트에 있을 때만** 경고 (편집기 안에서는 방해하지 않음)

→ 한 줄을 개행 없이 복사하면 조용히 들어가고, 웹에서 명령 블록을 통째로 긁으면 확인창이 뜨는 이유가 이것.

### 방어 3 — 브라우저 콘솔의 `allow pasting`
같은 위협 모델의 **웹 버전**이 [[Self-XSS]] 방지다. Chrome DevTools는 콘솔 붙여넣기 시 `allow pasting`을 **직접 타이핑**하게 만든다. 터미널이든 콘솔이든, **"남이 준 텍스트를 실행 지점에 그대로 붙여넣는 순간"** 에 마찰을 넣는다는 발상이 같다.

### 실무 수칙
- 웹에서 복사한 명령은 **에디터나 빈 줄에 먼저 붙여넣고 눈으로 확인**한 뒤 실행한다.
- 붙여넣기 후 **Enter 전에 한 번 읽기** — 하이라이트된 범위가 예상과 같은지.
- `curl … | sh` 처럼 **내용을 보지 않고 실행하는 관용구**는 같은 위험의 다른 얼굴이다.
- bracketed paste를 **끄지 말 것.** 붙여넣기가 이상하게 동작한다고 끄는 사례가 많은데, 그러면 방어가 통째로 사라진다.

## 왜 중요한가
- 개발자가 **하루에도 수십 번 하는 행동**(복사 → 터미널 붙여넣기)이 그대로 코드 실행 경로다. 터미널은 [[동일 출처 정책|브라우저 같은 샌드박스]]도 없이 **내 권한 전부**로 돈다.
- 클립보드는 앱의 것이 아니라 **시스템 공용 버퍼**라, 복사한 뒤 붙여넣기 직전까지 내용이 그대로라는 보장이 없다 → [[클립보드 자동 삭제와 시스템 클립보드]].

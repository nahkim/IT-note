# 이벤트 루프 (Event Loop)

## 한 줄 정의
**단일 스레드**인 JavaScript가 멈추지 않고 비동기 작업을 처리하도록, "콜스택이 비면 큐에서 다음 일을 꺼내 실행"하는 것을 반복하는 **조율 장치**.

## 자세히

### 등장인물
- **콜스택(Call Stack)** — 지금 실행 중인 함수들. **하나뿐**이다.
- **웹 API / 플랫폼** — `setTimeout`, `fetch`, DOM 이벤트, I/O처럼 **JS 밖(브라우저)** 에서 처리되는 일들.
- **매크로태스크 큐(Task Queue)** — `setTimeout`·`setInterval`·이벤트 콜백·`MessageChannel` 등.
- **마이크로태스크 큐(Microtask Queue)** — **Promise `.then`/`await` 이후**, `queueMicrotask`, `MutationObserver`.

### 한 바퀴의 순서
1. **동기 코드를 끝까지 실행**(콜스택이 빌 때까지).
2. **마이크로태스크 큐를 전부 비운다** — 도중에 추가된 마이크로태스크까지 모두.
3. 필요하면 **렌더링 갱신**(스타일·레이아웃·페인트).
4. **매크로태스크는 한 번에 하나만** 꺼내 실행 → 다시 2번으로.

> 🔑 **마이크로태스크는 매크로태스크 사이마다 완전히 비워진다.** 그래서 `Promise.then`은 항상 `setTimeout(…, 0)`보다 먼저 실행된다.

```js
console.log('1');
setTimeout(() => console.log('4'), 0);      // 매크로태스크
Promise.resolve().then(() => console.log('3')); // 마이크로태스크
console.log('2');
// 출력: 1 → 2 → 3 → 4
```

### 실무에서 물리는 지점
- **마이크로태스크 기아(starvation)** — 마이크로태스크가 무한히 자기를 다시 큐에 넣으면 매크로태스크와 **렌더링이 영원히 못 돈다** → 탭이 완전히 멈춤.
- **긴 작업(Long Task)** — 무거운 반복문 하나가 콜스택을 붙잡으면 클릭도 스크롤도 안 먹는다(**INP 악화**). 해법: 작업을 쪼개 `setTimeout`/`scheduler.yield`로 양보하거나, **[[웹 워커]]** 로 다른 스레드에 넘기기.
- **`setTimeout(fn, 0)`은 "즉시"가 아니다** — 최소 지연(중첩 시 약 4ms)이 있고, 앞의 태스크가 끝나야 실행된다. 백그라운드 탭에선 더 느려진다.
- **애니메이션은 `requestAnimationFrame`** — 다음 렌더링 직전에 실행되어 프레임과 정렬된다 ([[리플로우]]).
- **Node.js의 이벤트 루프는 구조가 다르다** — libuv 기반의 단계(phase) 모델에 `process.nextTick`·`setImmediate`가 추가된다. 개념은 같지만 세부 순서는 다르게 기억해야 한다.

## 왜 중요한가
- "JS는 싱글 스레드인데 어떻게 동시에 여러 일을 하지?"의 답. **비동기 코드의 실행 순서를 예측**할 수 있게 해준다 ([[동기와 비동기]]).
- UI 버벅임(jank)·응답 없음의 원인을 **"루프를 누가 붙잡고 있나"** 로 진단하게 해준다. 프론트엔드 성능 디버깅의 기본 프레임.

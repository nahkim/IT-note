# 셀프호스팅 (Self-hosting)

## 한 줄 정의
**남이 운영해 주는 서비스(SaaS)를 쓰는 대신, 소프트웨어를 내가 설치하고 내가 운영하는 것.** 핵심은 "서버가 어디 있느냐"가 아니라 **"운영 책임을 누가 지느냐"** — 클라우드 VPS를 빌려 돌려도 그 위의 업데이트·백업·장애 대응이 내 몫이면 셀프호스팅이다. 그래서 이 노트의 절반은 **얻는 것**이 아니라 **넘겨받는 책임**에 대한 이야기다.

## 자세히

### 좌표계 — 헷갈리는 네 가지를 한 표로
| | 소프트웨어 운영(업데이트·백업·가용성) | 인프라 소유 | 예 |
|---|---|---|---|
| **SaaS** | 제공자 | 제공자 | Notion, Slack, Gmail |
| **매니지드 서비스** | 제공자(대부분) | 제공자 | AWS RDS, Managed Kubernetes |
| **셀프호스팅 (클라우드)** | **나** | 제공자 | VPS에 올린 Nextcloud |
| **셀프호스팅 (온프레미스)** | **나** | **나** | 사내 서버룸의 GitLab |

**축이 두 개다**: *운영 책임*(셀프호스팅이 가리키는 축)과 *물리적 위치*(온프레미스가 가리키는 축). 두 단어를 섞어 쓰면 대화가 어긋난다. → [[온프레미스]]

### 왜 하나
- **비용** — 특히 **사용자당 과금(시트 기반)** SaaS. 인원이 늘수록 요금이 선형으로 늘지만 셀프호스팅은 대개 고정이다.
- **데이터 통제·프라이버시·규제** — 데이터가 내 디스크에만 있다. AI 시대에 "내 데이터가 학습에 쓰이는가"가 실질적 동기로 커졌다.
- **락인 회피** — 가격 인상, 기능 제거, 무료 플랜 축소, **서비스 종료**에 인질이 되지 않는다. 사실상의 *exit 전략*.
- **통제와 확장성** — 버전 고정, 플러그인, 소스 수정, 사내망 연동.
- **학습** — 홈랩은 운영 역량을 기르는 가장 값싼 훈련장이다.

### ⚠️ 대가 — "라이선스비 0원"이 "총비용 0원"이 아니다
셀프호스팅을 택하는 순간 **인수하는 책임 목록**:

- 설치·설정, 그리고 **보안 패치 추적**(내가 쓰는 소프트웨어의 CVE를 누가 보고 있나?)
- **백업 + 복구 리허설** — 백업이 있다는 것과 복구가 된다는 것은 다른 사실이다
- 가용성·모니터링·알림, 그리고 그걸 받는 사람 → [[온콜]] · [[런북]] · [[알람 피로]]
- 인증·권한·TLS 인증서 갱신, 스토리지 용량 관리, 버전 업그레이드 마이그레이션
- 새벽 3시에 서비스가 죽었을 때의 **대응자**

> **판단 질문은 "얼마 아끼나"가 아니다.** *이게 죽으면 누가 몇 분 안에 살리나, 그 사람이 휴가면 어떻게 되나* — **버스 팩터**가 실제 결정 기준이다. 내 시간을 0원으로 계산하면 셀프호스팅은 언제나 싸게 나온다.

### 2026년의 현실적인 스택
```
[사용자]
   │ ① 포트를 열지 않는 접근
   │    · Tailscale/WireGuard 메시 (사설망처럼)
   │    · Cloudflare Tunnel·Pangolin (아웃바운드 터널)
   ▼
[리버스 프록시 + 자동 TLS]   Caddy · Traefik · Nginx Proxy Manager
   │ ② SSO/포워드 인증        Authentik · Authelia
   ▼
[컨테이너 묶음]   대부분 Docker Compose 한 파일로 충분. 규모가 커지면 k3s
   │
   ├─ 앱들 (아래 표)
   ├─ 관측: Grafana + Prometheus, Uptime Kuma
   └─ 백업: restic/borg → S3 호환 스토리지(B2·R2·Hetzner)
```
- **실행** — 예전엔 쿠버네티스가 필요해 보였던 일이 지금은 **Docker Compose로 끝난다.** → [[컨테이너와 Docker]] · [[쿠버네티스]]
- **노출 최소화** — 인바운드 포트를 아예 열지 않고 **내가 먼저 나가서 연결하는** 방식이 기본값이 됐다([[셀프호스티드 러너]]와 정확히 같은 원리).
- **플랫폼화** — Coolify·Dokploy·CapRover는 셀프호스팅판 PaaS(git push 배포), Proxmox·TrueNAS·Unraid는 하이퍼바이저·NAS 층.
- **백업은 3-2-1** — 사본 3부, 매체 2종, **오프사이트 1부**. 암호화해서 오브젝트 스토리지로 보내고, **복구를 주기적으로 실제로 해본다.** → [[드라이런]]
- **자동 업데이트는 양날의 칼** — Watchtower류로 전부 최신화하면 파괴적 변경에 그대로 맞는다. **태그 고정 + 릴리즈 노트 확인 + 스냅샷 후 갱신**이 안전한 기본기.

### ⚠️ 라이선스 함정 — 셀프호스팅 권리는 회수될 수 있다
2023년 이후 "오픈소스였던 것"들이 대거 **source-available 라이선스**로 옮겨갔다.

| 프로젝트 | 흐름 |
|---|---|
| **Terraform** | MPL → **BUSL 1.1**(2023-08) → 커뮤니티가 포크해 **OpenTofu**(Linux Foundation, 2023-09) |
| **Redis** | BSD-3 → **RSALv2/SSPL**(2024-03) → **Valkey** 포크 등장 → Redis 8에서 **AGPLv3 추가**(2025-05) |
| **Elasticsearch·Kibana** | Apache 2.0 → **SSPL**(2021) → **AGPL 추가로 복귀**(2024-08), 그사이 **OpenSearch** 포크가 자리 잡음 |

**정리해 둘 것**
- **source-available ≠ 오픈소스.** SSPL·BUSL은 소스를 볼 수 있지만 **OSI 승인 라이선스가 아니다.**
- 대부분의 source-available 라이선스는 *"경쟁 서비스로 제공하지 말 것"*을 막는 것이고, **자기 조직 내부용 셀프호스팅은 보통 허용**된다. 그래도 **쓰기 전에 조건을 직접 읽어야 한다**(사용자 수 제한, 상업적 사용, 매니지드 제공 금지).
- **오픈코어의 "SSO 세금"** — 무료 셀프호스팅판에서 SSO·감사 로그·세밀한 권한이 빠져 있는 경우가 흔하다. 기업 도입 시 여기서 계산이 뒤집힌다. → [[OIDC]]

### 셀프호스팅하지 말아야 할 것
- **메일 서버** — SPF/DKIM/DMARC와 IP 평판 싸움. 보내도 스팸함에 꽂히면 아무 의미가 없다. 대표적인 "하지 마라" 항목.
- **결제·카드 데이터** — PCI DSS 적용 범위를 내 손으로 끌어안는 선택이 된다. → [[WAF]] · [[ISMS]]
- **회사 전체가 의존하는 도구를 담당자 1명이 운영**하는 구조(버스 팩터 1).
- 감사·규제 대응 인력이 없는 팀의 **대량 개인정보 처리**.
- 절감액은 월 몇만 원인데 운영 시간이 월 몇 시간 드는 경우 — **계산이 안 맞는다.**

### 도입 전 체크리스트
- [ ] 데이터 민감도와 규제 적용 여부
- [ ] 허용 다운타임(RTO)·허용 데이터 손실(RPO)
- [ ] 1차 담당자 **와 대체자**
- [ ] 백업 방식 + **복구 검증 주기**
- [ ] 업데이트·CVE 추적 담당
- [ ] 총비용(하드웨어·전기·스토리지 + **사람 시간**) vs SaaS 요금
- [ ] 라이선스 조건과 포크 존재 여부
- [ ] 3년 뒤에도 이 운영을 유지할 수 있는가, 아니면 **SaaS로 되돌아갈 경로**가 있는가

## 왜 중요한가
- **판이 다시 셀프호스팅에 유리해졌다.** 클라우드 비용은 오르고 하드웨어는 싸졌으며, 컨테이너 생태계가 성숙해 예전엔 팀이 필요했던 운영을 Compose 파일 하나로 한다.
- **데이터 주권이 실질 이슈가 됐다.** "우리 문서가 어느 회사 모델의 학습 데이터가 되는가"가 도입 심사 항목이 되는 시대다.
- **벤더 리스크 관리 수단**이다. 가격 인상·기능 제거·서비스 종료에 대한 대비책을 가진 팀과 없는 팀의 협상력은 다르다.
- **동시에 가장 흔한 실패는 화려한 장애가 아니라 조용한 방치다** — 인터넷에 노출된 채 패치되지 않은 인스턴스, 한 번도 복구를 시도해 본 적 없는 백업. 셀프호스팅의 난이도는 설치가 아니라 **2년째 운영**에 있다.
- 개인에게는 **운영을 배우는 가장 좋은 놀이터**이고, 조직에게는 **책임 이전 계약**이다. 같은 기술이 맥락에 따라 전혀 다른 결정이 된다.

# 개발자 도구 (DevTools)

## 한 줄 정의
브라우저에 내장된 **웹 디버깅·검사 도구** — 페이지의 DOM·스타일·네트워크·성능·저장소를 실시간으로 들여다보고 고칠 수 있다. (`F12` / `Cmd+Opt+I`)

## 자세히

### 주요 패널
- **Elements(요소)** — 현재 **[[DOM]]** 트리와 적용된 CSS를 보고 즉석에서 수정. ⚠️ 여기 보이는 건 원본 HTML이 아니라 **JS 실행 후의 DOM**이다.
- **Console(콘솔)** — 로그 출력과 **JS 즉시 실행**. 가장 강력하고, 그래서 **[[Self-XSS]]** 의 무대이기도 하다.
- **Sources(소스)** — 소스 파일 조회, **중단점(breakpoint)** 디버깅, 스텝 실행, 소스맵으로 번들 이전 코드 보기, 로컬 파일과 연결(Workspace).
- **Network(네트워크)** — 모든 요청/응답의 헤더·본문·타이밍·상태 코드. [[CORS]] 에러, 캐시 적중, 느린 요청 진단의 출발점. 요청을 **cURL로 복사**([[curl]])하는 기능이 실무에서 특히 유용.
- **Performance(성능)** — 런타임 프로파일링. 어느 함수가 오래 잡고 있는지, [[리플로우]]가 몇 번 터졌는지, 프레임이 왜 밀리는지.
- **Memory(메모리)** — 힙 스냅샷으로 **메모리 누수** 추적 ([[가비지 컬렉션과 메모리]]).
- **Application(애플리케이션)** — 쿠키·localStorage·IndexedDB·Cache Storage·[[서비스 워커]] 상태 확인·삭제 ([[브라우저 저장소]]).
- **Security / Lighthouse** — 인증서·혼합 콘텐츠 점검, 성능·접근성·SEO·모범 사례 자동 감사 리포트.

### 자주 쓰는 기법
- **디바이스 툴바**(`Cmd/Ctrl+Shift+M`) — 모바일 화면·터치·네트워크 속도 제한(throttling) 시뮬레이션.
- **CPU 스로틀링** — 저사양 기기 재현. 데스크톱에선 안 보이던 성능 문제가 드러난다.
- **조건부 중단점 / XHR·이벤트 중단점** — `console.log` 도배 대신 조건을 걸어 멈춘다.
- **네트워크 요청 오버라이드·차단** — 서버 없이 응답을 바꿔 프론트 동작 확인.
- **커버리지(Coverage)** — 안 쓰이는 CSS/JS 비율 확인 → 번들 다이어트.
- **`$0`** — Elements에서 선택한 요소를 콘솔에서 바로 참조.

### 보안상 알아둘 것
- 콘솔에서 실행한 코드는 **그 사이트의 정식 스크립트와 동일한 권한**을 가진다. 그래서 Chrome은 붙여넣기 시 `allow pasting` 입력을 요구하는 **self-XSS 보호**를 넣었다 → [[Self-XSS]].
- 반대로, 클라이언트에 내려간 것은 **전부 사용자가 볼 수 있다**는 사실도 여기서 확인된다: 프론트엔드에 숨긴 API 키·비밀은 숨겨지지 않는다 ([[환경 변수]]).

## 왜 중요한가
- **웹 개발자의 기본 계측기.** "왜 안 되지?"를 추측이 아니라 **관측**으로 바꾼다 ([[러버덕 디버깅]]과 함께 디버깅의 기본기).
- 성능·보안·네트워크 문제를 **한 자리에서** 재현·측정할 수 있어, 서버 로그를 뒤지기 전에 대부분의 프론트 이슈가 여기서 판가름 난다.

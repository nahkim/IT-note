# 애플리케이션 형태 (앱은 몇 가지가 있나)

## 한 줄 정의
소프트웨어가 **사용자를 만나는 겉모습**의 분류. 흔히 "데스크톱 앱·웹·앱 셋"으로 뭉뚱그리지만, 이 셋은 **서로 다른 기준이 섞인 말**이고 실제 형태는 훨씬 많다.

## 자세히

### 먼저, 흔한 3분류가 어긋나는 이유
| 흔히 말하는 것 | 실제로는 무슨 기준인가 |
|---|---|
| **웹** | 실행 **환경**(브라우저 안에서 돈다) |
| **데스크톱 / 모바일** | 실행 **기기**(PC냐 폰이냐) |
| **앱** | 그냥 **통칭** — 웹앱도 앱이고 CLI도 앱이다 |

기준이 섞여 있으니 "PWA는 웹이야 앱이야?", "[[Tauri]]로 만든 건 데스크톱 앱이야 웹이야?" 같은 질문이 끝나지 않는다. **축을 먼저 나누면** 깔끔해진다.

### 축 4개로 나눠 보기
1. **접점(인터페이스)** — GUI / 브라우저 화면 / 명령줄 / 터미널 화면 / 대화(챗·음성) / **UI 없음**
2. **실행 기기** — 데스크톱 · 모바일 · 서버 · 임베디드 · 워치 · TV · 차량 · XR 헤드셋
3. **구현 방식** — 네이티브 / 웹 / 웹뷰 하이브리드 / 크로스플랫폼 → 이 축은 [[클라이언트 앱]]·[[네이티브 앱]]에서 다룬다
4. **배포 경로** — 앱스토어(심사 있음) / 설치 파일 / URL 접속(배포 즉시) / 패키지 매니저(`brew`·`npm`) / 컨테이너 이미지

같은 제품이 축마다 다른 칸에 놓일 수 있다. Tauri 앱은 **접점=GUI, 기기=데스크톱, 구현=웹뷰, 배포=설치 파일**이다. "웹이냐 앱이냐"는 애초에 답이 없는 질문인 것.

### 형태 카탈로그
| 형태 | 사용자가 만나는 방식 | 예 | 관련 노트 |
|---|---|---|---|
| **웹앱** | 브라우저 접속, 설치 없음 | Gmail, Notion, Figma | [[CORS]] · [[REST API]] |
| **PWA** | 웹인데 설치·오프라인·푸시까지 | 스타벅스 PWA | [[서비스 워커]] |
| **데스크톱 GUI 앱** | 설치해서 창으로 씀 | VS Code, Slack | [[Tauri]] · [[Wails]] |
| **모바일 앱** | 스토어에서 설치 | 카카오톡, 인스타그램 | [[네이티브 앱]] · [[크로스플랫폼]] |
| **CLI** | 터미널에 명령어를 입력 | `git`, `curl`, `gh` | [[표준 스트림]] · [[curl]] |
| **TUI** | 터미널 안의 화면 UI | `htop`, `vim`, `lazygit` | [[표준 스트림]] |
| **데몬 / 서비스** | **UI가 없다.** 계속 떠 있으며 뒤에서 일함 | nginx, sshd, 백업 에이전트 | [[systemd]] |
| **배치 / 크론 잡** | 정해진 시각에 돌고 끝남 | 야간 정산, ETL | [[성능 SLA]] |
| **브라우저 확장** | 브라우저에 얹혀 웹을 바꿈 | 광고 차단, 번역 | [[extension]] |
| **플러그인 / 애드온** | 남의 앱 안에서 동작 | Obsidian 플러그인, VS Code 확장 | [[extension]] |
| **봇 / 챗 앱** | 대화창이 UI다 | Slack 봇, 디스코드 봇 | [[AI 에이전트]] |
| **음성 앱** | 말로 쓴다 | 스마트 스피커 스킬 | [[STT 음성 인식]] |
| **임베디드 / 펌웨어** | 기기 자체가 된다 | 공유기, 프린터, IoT | [[온디바이스]] |
| **키오스크 / 사이니지** | 전용 하드웨어에 전체화면으로 고정 | 무인 주문기, 광고판 | — |
| **워치 · TV · 차량 · XR** | 작은 화면·리모컨·핸드트래킹 | 워치 앱, TV 앱, 차량 인포테인먼트 | — |
| **미니앱** | 다른 앱 **안에서** 도는 앱 | 카카오 싱크, 위챗 미니프로그램 | — |
| **게임** | 자체 렌더링 루프·콘솔 | 콘솔·PC 게임 | [[GPU vs CPU]] |
| **라이브러리 / SDK** | 사용자가 사람이 아니라 **다른 개발자** | `requests`, AWS SDK | [[바인딩]] · [[FFI]] |
| **headless 서버 / API** | UI가 없고 다른 프로그램이 호출 | REST 서버, gRPC 서비스 | [[REST API]] · [[FastAPI]] |
| **서버리스 함수** | 요청이 올 때만 깨어나 실행 | Lambda 함수 | [[서버리스]] |
| **에이전트 도구 / MCP 서버** | LLM이 호출하는 도구가 곧 인터페이스 | MCP 서버, 툴 정의 | [[AI 에이전트]] |

### 하나의 제품은 보통 여러 형태를 동시에 갖는다
GitHub 하나만 봐도 **웹앱 + 데스크톱 앱 + 모바일 앱 + CLI(`gh`) + API + 배치(Actions)** 를 전부 갖고 있다. "우리 서비스는 어떤 형태냐"가 아니라 **"어떤 형태들을 낼 것이냐"** 가 실제 질문이다.

### 고를 때 실제로 갈리는 것들
- **배포 속도** — 웹은 고치면 **즉시** 전원에게 반영. 스토어 앱은 **심사**를 기다리고, 데스크톱 앱은 사용자가 업데이트를 받아야 한다. → [[릴리즈]] · [[무중단 배포]]
- **버전 파편화** — 웹은 항상 최신 하나. 설치형은 **구버전이 세상에 남아** 서버가 오래된 클라이언트를 계속 지원해야 한다.
- **기기 권한** — 파일 시스템 전체, 백그라운드 상주, 시스템 트레이, USB·시리얼 접근은 여전히 설치형의 영역이다. (카메라·GPS·푸시·오프라인 저장은 이제 브라우저에서도 상당히 된다.)
- **자동화 가능성** — CLI는 파이프로 **다른 도구와 조합**된다. GUI는 사람 손이 있어야 한다. 개발자 대상 도구에서 CLI를 얹는 이유.
- **빌드·유지 비용** — 형태를 늘릴 때마다 [[툴체인]]과 테스트 대상이 늘어난다. → [[크로스플랫폼]]
- **오프라인** — 필요하면 설치형이나 PWA로, 아니면 웹으로.

## 왜 중요한가
- **"앱 만들자"는 말은 아무것도 정하지 않은 문장이다.** 어떤 형태로 낼지에 따라 배포 주기·팀 구성·기술 스택·테스트 범위가 전부 달라진다.
- **형태를 잘못 고르면 되돌리기가 비싸다.** 스토어 앱으로 시작했다가 "배포가 느려서 웹으로 옮긴다"는 사실상 재작성이다.
- **의외로 UI 없는 형태가 다수다.** 데몬·배치·API·라이브러리는 화면이 없지만 실제 소프트웨어의 큰 몫을 차지한다. "앱 = 화면"이라는 감각이 시야를 좁힌다.
- **새 형태는 계속 생긴다.** 미니앱, XR, 그리고 최근에는 **LLM이 호출하는 도구(MCP 서버)** 처럼 *사용자가 사람이 아닌* 형태까지 늘고 있다.

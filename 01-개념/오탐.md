# 오탐 (False Positive)

## 한 줄 정의
**아무 일도 없었는데 "있다"고 울리는 것.** 탐지하는 모든 시스템(보안 장비·백신·[[WAF]]·코드 스캐너·스팸 필터·모델 평가)은 두 가지로 틀릴 수 있는데, 그중 **없는 걸 있다고 한 쪽이 오탐**, **있는 걸 없다고 한 쪽이 미탐**이다. 실무에서 중요한 건 "오탐률이 몇 %냐"가 아니라 **"울린 경보 중 진짜가 몇 개냐"** — 이 둘은 전혀 다른 숫자다.

## 자세히

### 용어부터 맞추기 — 오탐 vs 미탐
|  | **탐지가 "공격이다"** | **탐지가 "정상이다"** |
|---|---|---|
| **실제로 공격** | ✅ 정탐 (TP, True Positive) | ❌ **미탐** (FN, False Negative) — 뚫린다 |
| **실제로 정상** | ❌ **오탐** (FP, False Positive) — 시끄럽다 | ✅ 정상 판정 (TN, True Negative) |

- **오탐** = false positive = 오경보(false alarm) = 통계의 **1종 오류**.
- **미탐** = false negative = 누락 = **2종 오류**.

> ⚠️ 한국어 회의에서 **"오탐"이 "잘못 탐지한 것 전부"**라는 넓은 뜻으로 쓰여 미탐까지 섞여 불리는 일이 잦다. 숫자를 논하기 전에 **"지금 말하는 오탐이 FP냐 FN이냐"**부터 합의할 것. 여기서 갈리면 이후 튜닝 방향이 정반대가 된다.

### 하나를 줄이면 다른 하나가 는다
탐지는 대부분 **임계값(threshold) 하나를 어디에 두느냐**의 문제다.

```
  느슨하게(임계값↓)          ←───────────────→          엄격하게(임계값↑)
  다 잡는다                                              확실한 것만 잡는다
  미탐 ↓  오탐 ↑                                        오탐 ↓  미탐 ↑
  "경보가 하루 3000건"                                   "조용한데… 뚫린 건 아닐까"
```

이걸 재는 지표:

| 지표 | 식 | 읽는 법 |
|---|---|---|
| **정밀도 (Precision)** | TP / (TP + FP) | **울린 경보 중 진짜의 비율** — 분석가의 체감 품질 |
| **재현율 (Recall) = 탐지율** | TP / (TP + FN) | **진짜 공격 중 잡아낸 비율** — 보안의 체감 안전 |
| **오탐률 (FPR)** | FP / (FP + TN) | **정상 트래픽 중 잘못 울린 비율** — 벤더가 좋아하는 숫자 |
| **F1** | 정밀도·재현율의 조화평균 | 둘의 균형을 한 숫자로 |
| **정확도 (Accuracy)** | (TP+TN) / 전체 | ⚠️ **희귀 사건에선 무의미** (아래 참고) |

> ⚠️ **FPR과 (1 − 정밀도)는 다른 값이다.** 벤더 자료의 "오탐률 0.1%"는 거의 항상 FPR이고, 운영자가 겪는 고통은 정밀도 쪽이다. 두 숫자가 얼마나 벌어지는지가 다음 항목.

### 기저율의 함정 — "오탐률 0.1%"가 현장에선 절반이 오탐이 되는 이유
하루 요청 **100만 건**, 그중 실제 공격이 **100건(0.01%)**인 서비스. 탐지율 99%, 오탐률 0.1%짜리 "우수한" 장비를 붙이면:

```
진짜 공격 100건 × 99%        =    99건  ← 정탐
정상 999,900건 × 0.1%        = 1,000건  ← 오탐
────────────────────────────────────────
울린 경보                      1,099건
그중 진짜                         99건  →  정밀도 9%
```

**경보 11건을 까 봐야 진짜 1건**이 나온다. 장비 성능이 나빠서가 아니라 **공격이 애초에 희귀해서** 생기는 구조적 결과다. 이걸 **기저율의 함정(base rate fallacy)**이라 하고, 침입탐지에서는 Axelsson의 1999년 논문(*The base-rate fallacy and the difficulty of intrusion detection*)이 "**IDS의 성능을 결정하는 것은 탐지율이 아니라 오탐률**"이라고 못 박은 이래 이 분야의 기본 상식이 됐다.

같은 이유로 **정확도(accuracy)는 이런 데서 쓰면 안 된다.** 위 예에서 "전부 정상"이라고 찍기만 해도 정확도는 99.99%다.

**실무 함의**
- 희귀할수록 정밀도가 무너진다 → **모수를 줄이는 게 임계값 조정보다 효과적일 때가 많다**(자산·경로별로 룰을 좁히기, 사전 필터링).
- 기저율을 **인위적으로 뒤집은 신호**가 귀한 이유가 여기 있다 → [[허니팟]](건드릴 이유가 없는 미끼이므로 접근 자체가 거의 정탐).

### 오탐의 진짜 비용 — 알람 피로와 "poisoned well"
- 2026년 **Microsoft/Omdia State of the SOC** 기준 전체 경보의 **46%가 오탐**, 잘 튜닝되지 않은 조직은 80%를 넘기도 한다.
- **SANS 2025 Detection & Response 설문**: 보안팀 **73%가 "오탐"을 최대 난제**로 꼽음. 분석가는 근무시간의 **25% 이상**을 오탐 처리에 쓰고, 경보의 상당수는 **아예 조사되지 않는다**.
- 개발 쪽도 같다. SAST(정적 분석) 경고는 **절반 이상이 이력상 한 번도 처리되지 않으며**, 개발자들이 감내한다고 답하는 오탐 한계선은 대략 **20% 미만**이다.

여기서 생기는 게 **양치기 소년 효과(poisoned well syndrome)** — *"대부분이 노이즈"라고 학습한 순간, 진짜 경보까지 노이즈로 취급된다.* 오탐의 비용은 "확인하는 시간"이 아니라 **탐지 체계 전체의 신뢰 상실**이다.

> ⚠️ **차단형 시스템에서 오탐 = 장애다.** [[WAF]]가 정상 결제 요청을 막으면 그건 경보가 아니라 매출 손실이고, 스팸 필터가 계약서 메일을 버리면 사고다. 그래서 차단은 거의 항상 **탐지(모니터링) 모드 선배포 → 튜닝 → 전환** 순서를 밟는다. [[CSP]]의 `Report-Only`, WAF의 detection mode가 같은 발상이다.

### 어느 쪽 오류가 더 비싼가 — 절대 대칭이 아니다
| 영역 | 더 비싼 쪽 | 그래서 어떻게 |
|---|---|---|
| 스팸 필터 | **오탐**(정상 메일 유실) | 보수적으로 — 웬만하면 통과, 애매하면 격리함 |
| 1차 침입탐지·건강검진 | **미탐**(놓치면 끝) | 민감하게 잡고 **2차 정밀 검사**로 걸러냄 |
| 차단형 WAF·FDS | **오탐**(정상 사용자 차단) | 확실한 것만 차단, 나머지는 로그·챌린지(CAPTCHA) |
| 코드 스캐너(SAST) | **오탐**(개발자 이탈) | 정밀도 높은 룰만 CI 차단, 나머지는 리포트 |
| 백신 | **오탐**(시스템 파일 격리 → 부팅 불가) | 화이트리스트·서명 기반 예외 |

**"오탐을 줄이자"는 목표가 아니라 방향이다.** 진짜 질문은 *오탐 1건과 미탐 1건 중 어느 쪽이 우리에게 몇 배 비싼가* → 이 비율이 임계값을 정한다.

### 오탐을 줄이는 실무 수단
1. **탐지 모드로 먼저 돌려 베이스라인 수집** — 우리 트래픽에서 뭐가 울리는지부터 본다.
2. **룰 단위가 아니라 (룰 × 경로 × 파라미터) 단위 예외** — 룰 전체를 끄면 그 룰의 탐지력이 통째로 사라진다.
3. **점수 누적(anomaly scoring)** — 룰 하나 걸렸다고 바로 차단하지 않고, 점수가 임계치를 넘을 때만. → [[WAF]]의 OWASP CRS가 쓰는 방식.
4. **컨텍스트 결합** — 자산 중요도, 사용자 이력, 위협 인텔리전스, 다른 로그와의 상관분석. 같은 신호라도 맥락이 붙으면 정밀도가 올라간다.
5. **다단계 파이프라인** — 값싼 필터로 모수를 줄이고, 살아남은 것만 비싼 검증에 태운다.
6. **중복 제거·억제(suppression)·등급화** — 같은 원인의 경보 500건을 1건으로.
7. **오탐을 회귀 테스트로 박제** — "이 요청은 통과해야 한다"를 케이스로 남겨야 다음 룰 업데이트에서 재발하지 않는다. → [[소프트웨어 테스트]]
8. **사람/LLM 트리아지 루프** — 최근 SOC 자동화의 핵심이 1차 판별 자동화다.

### AI 시대의 오탐
- **LLM 트리아지**는 오탐을 줄이는 수단이면서 **자기 자신이 오탐·미탐의 원천**이다. "그럴듯하게 설명된 오탐"은 사람이 거르기 더 어렵다. → [[LLM]] · [[프롬프트 엔지니어링]]
- **LLM 심사(LLM-as-judge)·모델 평가**도 정확히 같은 2×2로 측정된다. 평가지표를 정밀도만 보고하면 재현율이 숨는다.
- **환각(hallucination)과 오탐은 다른 개념**이다. 환각은 근거 없는 생성, 오탐은 판정 오류 — 다만 탐지 파이프라인에 LLM을 얹으면 두 가지가 겹쳐서 나타난다.

## 왜 중요한가
- **탐지 시스템의 품질은 "무엇을 잡았나"가 아니라 "얼마나 조용한가"로 결정된다.** 오탐이 많은 탐지기는 결국 꺼지거나 무시되고, 그 순간 탐지율 99%는 0%가 된다.
- **기저율 감각이 없으면 벤더 수치에 속는다.** 오탐률 0.1%가 정밀도 9%로 바뀌는 계산을 할 줄 아는 것이, 보안 장비·AI 모델 도입 판단의 기본기다.
- **오탐/미탐의 비용 비율을 정하는 건 기술이 아니라 비즈니스 결정**이다. 이 합의 없이 임계값을 만지면 튜닝이 영원히 끝나지 않는다.
- 보안뿐 아니라 **모니터링 알림, 테스트(플래키 테스트), 추천·필터링, 의료·금융 심사**까지 같은 틀이 그대로 적용된다.

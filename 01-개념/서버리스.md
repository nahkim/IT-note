# 서버리스 (Serverless)

## 한 줄 정의
서버가 "없는" 게 아니라 **서버 프로비저닝·운영·확장을 클라우드가 대신** 맡아, 개발자는 **코드(함수)만** 올리면 되는 실행 모델. 요청이 올 때만 실행되고 **쓴 만큼만** 낸다.

## 자세히

### 두 갈래
- **FaaS (Function as a Service)** — 이벤트에 반응하는 **함수** 단위 실행. AWS **Lambda**, Google Cloud Functions, Azure Functions, Cloudflare Workers.
- **BaaS (Backend as a Service)** — 인증·DB·스토리지 같은 **관리형 백엔드**. Firebase, Supabase. (실제 앱은 보통 FaaS + BaaS 조합)

### 특징
- **이벤트 기반** — HTTP 요청·파일 업로드·큐 메시지·스케줄 등이 트리거.
- **자동 확장(0 → N)** — 요청 없으면 0으로 줄고, 몰리면 자동으로 인스턴스 증가.
- **사용량 과금** — 요청 수·실행 시간(ms)으로 과금. **놀 때는 0원.**
- **서버 관리 없음** — 패치·스케일·가용성은 제공자 몫.

### 제약 (꼭 알아둘)
- **콜드 스타트** — 안 쓰던 함수의 첫 호출 시 초기화 지연(Node/Python ~200~400ms, Java/C# 2초+). 상시 쓰는 함수는 <1%만 해당. 완화: SnapStart·provisioned/관리형 인스턴스. → [[레이턴시]]
- **실행 시간 제한** — 함수당 상한(예: Lambda 15분). 장기 작업 부적합.
- **상태 없음(stateless)** — 호출 간 상태가 유지 안 됨(상태는 외부 저장소·[[메시지 큐]]로).
- **벤더 락인**, 관측·디버깅 난이도.

### 언제 쓰나 — 예시와 함께
**✅ 잘 맞음 (이벤트 기반·간헐적·짧은 작업)**
- **파일 처리** — S3에 이미지 업로드 → Lambda 트리거로 **썸네일 생성/리사이즈**.
- **가벼운 API 백엔드** — [[API 게이트웨이]] + Lambda로 REST 엔드포인트(트래픽 변동 큰 서비스).
- **예약/스케줄 작업(cron)** — 매일 리포트 생성, 로그 정리, 만료 데이터 삭제.
- **웹훅 처리** — 결제·GitHub 웹훅 수신 후 후처리.
- **알림·챗봇** — 이벤트 발생 시 Slack/이메일 발송.
- **데이터 파이프라인 조각(ETL)** — 스트림 이벤트마다 변환.
- **프로토타입/MVP** — 인프라 없이 빠르게([[PoC와 파일럿]]).
- **스파이크성 트래픽** — 평소 0, 가끔 폭증(프로모션·이벤트).

**❌ 안 맞음 (컨테이너/서버로)**
- **장기 실행·무거운 연산** — ML 학습, 긴 배치, 영상 인코딩(시간·비용 한계).
- **초저지연 상시 서비스** — 콜드 스타트가 문제.
- **예측 가능한 대규모 상시 트래픽** — 전용 서버/컨테이너가 더 쌀 수 있음.
- **상태 유지 연결** — WebSocket 장기 연결·인메모리 상태(별도 설계 필요).

### vs 컨테이너 / 쿠버네티스
- **다른 문제를 푼다** — 컨테이너([[쿠버네티스]])는 제어·이식성·상시 서비스, 서버리스는 관리 부담 0·자동 스케일·이벤트.
- 추상화 스펙트럼: **[[온프레미스]] → VM → 컨테이너/K8s → 서버리스** (뒤로 갈수록 관리 부담↓·추상화↑).
- **Google Cloud Run** 등은 "컨테이너를 서버리스처럼" 돌려 둘 사이를 메운다.
- (2026) **엣지 서버리스(<10ms)**·**WASM**(콜드 스타트 거의 0)·GenAI/RAG·**상태형 서버리스**(Step Functions·Durable Functions)로 확장 중.

## 왜 중요한가
- **운영 부담을 걷어내고 사용량만큼만** 내니, 이벤트·간헐 워크로드에서 비용·속도가 압도적. 스타트업·프로토타입·글루 코드의 기본 선택지.
- 핵심은 **"언제 서버리스 / 언제 컨테이너"** 를 워크로드 성격으로 가르는 것([[트레이드오프]]).

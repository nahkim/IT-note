# LLM 모델 이름 읽는 법 (네이밍 규칙)

## 한 줄 정의
`gemma-2-9b-it-Q4_K_M` 처럼 길게 붙은 모델 이름은 **여러 정보를 `-`로 이어붙인 것**이다. 대체로 **`{패밀리}-{세대}-{크기}-{튜닝종류}-{양자화/포맷}`** 순서이고, 뒤에 부가 접미사가 더 붙는다. 각 조각이 뭘 뜻하는지 알면 **"이 모델이 내 GPU에 뜨나, 대화용인가"** 를 이름만 보고 판단할 수 있다.

## 자세히 — 조각별 뜻

### 1️⃣ 패밀리 (family) — "누가 만든 어떤 계열"
- 모델 **계열 이름**. 예: `Llama`(Meta), `Gemma`(Google), `Qwen`(Alibaba), `Mistral`/`Mixtral`(Mistral), `Phi`(Microsoft), `DeepSeek`, `GPT`(OpenAI).
- 허깅페이스에선 앞에 **조직 이름**이 `/`로 붙기도 한다: `google/gemma-2-9b-it`, `meta-llama/...`. (`TheBloke/`·`bartowski/` 처럼 **양자화 재배포자** 이름이 앞에 오면, 원본을 남이 변환해 올린 것)

### 2️⃣ 세대 / 버전 (generation) — "몇 번째 버전인가"
- 패밀리의 **버전 번호**. `Llama 3`, `Gemma 2`, `Qwen2.5`. 소수점(마이너 버전)도 흔함: `3.1`, `3.2`.
- 숫자가 클수록 최신. 같은 크기라도 **세대가 높으면 대체로 더 똑똑**하다.

### 3️⃣ 크기 (size) — "파라미터 수 = 대략의 덩치"
- `7B`, `8B`, `70B`, `2B` 처럼 **B = billion(10억) 파라미터 수**. 클수록 똑똑하지만 **메모리·연산도 그만큼** 필요. → [[GPU vs CPU]] · [[온디바이스 모델 배포]]
- **아주 거친 VRAM 감**: 16비트면 "파라미터 수 × 2GB"쯤(7B≈14GB), 4비트로 양자화하면 대략 그 1/4(7B≈4~5GB).
- **MoE(전문가 혼합) 표기**: `8x7B`(7B 전문가 8개), `A3B`처럼 **A = 활성(active) 파라미터**를 뜻함(예: `Qwen3-30B-A3B` = 총 30B인데 한 번에 3B만 켜서 씀) → 크기 대비 빠름.

### 4️⃣ 튜닝 종류 (tuning) — "그냥 원석인가, 대화용으로 다듬었나"
가장 헷갈리지만 **제일 중요한** 조각. 용도가 갈린다. → [[파인튜닝]]
- **`base` / (아무것도 없음)** — **사전학습만 한 원석**. 다음 단어 예측만 잘함. 채팅처럼 지시를 따르진 못함(추가 파인튜닝용).
- **`-it`** = **instruction-tuned**(지시 튜닝). Gemma가 쓰는 표기. = 대화·지시 수행용.
- **`-Instruct`** — 같은 뜻(Llama·Qwen 등이 씀). **지시/대화용**.
- **`-Chat`** — 대화용으로 튜닝(예전 Llama-2 표기).
- **`-Coder` / `-Code`** — 코드 특화. **`-Math`** — 수학 특화.
- **`-VL` / `-Vision`** — 이미지도 보는 **멀티모달**.
- **`-R1` / `-Reasoning` / `-Thinking`** — 추론(사고사슬) 특화.
- **`-Distill(ed)`** — 큰 모델의 능력을 **작은 모델로 증류**한 것(예: `DeepSeek-R1-Distill-Qwen-7B` = R1의 추론을 Qwen 7B에 이식).

> 💡 로컬에서 "말을 안 듣는다"의 흔한 원인: **base 모델을 받아서 채팅에 쓴 것.** `-it`/`-Instruct`가 붙은 걸 받아야 한다.

### 5️⃣ 양자화 / 포맷 (quantization / format) — "정밀도를 낮춰 가볍게 + 어떤 파일 형식"
가중치의 **숫자 정밀도를 낮춰** 용량·메모리를 줄인 것. 낮출수록 가볍지만 품질이 조금 떨어진다.
- **정밀도(원본)**: `FP32`(32비트) → `FP16`/`BF16`(16비트, 사실상 표준) → `FP8`.
- **양자화 비트**: `INT8`(8비트), `INT4`/`4bit`(4비트) 등. 숫자가 작을수록 가볍고 품질↓.
- **포맷(파일 형식/방식)** — 어디서 돌릴지가 갈린다:
  - **`GGUF`** — llama.cpp/Ollama용. **CPU·Mac(애플 실리콘)** 에서 잘 돌고 일부 레이어만 GPU로 넘기기 좋음. (구버전 `GGML`은 폐기 → GGUF로 대체)
  - **`GPTQ`** — **GPU 추론용** 4비트 사후 양자화.
  - **`AWQ`** — 활성값을 관찰해 **중요한 가중치를 보호**하는 방식. GPTQ보다 빠르고 품질도 비슷/더 나은 경우. 특히 지시튜닝 모델에 강점.
  - **`EXL2`**(ExLlamaV2)·**`MLX`**(애플 실리콘)·**`bitsandbytes`**(on-the-fly) 등도 있음.

#### GGUF 접미사 읽기 (예: `Q4_K_M`)
- **`Q4`** — **4비트** 양자화(Q 뒤 숫자 = 비트 수. `Q8`=8비트).
- **`_K`** — **그룹별 스케일**을 쓰는 K-quant(그냥 `_0`은 텐서 전체에 스케일 하나 = 옛 방식).
- **`_M`** — 품질 등급 **M=중간(medium)**. `_S`=작게(small), `_L`=크게(large). M은 중요한 어텐션 레이어에 비트를 더 준다.
- 감: **`Q4_K_M`** = 용량↓ + 품질 손실 1~3%로 **가성비 기본값**. **`Q8_0`** = 거의 무손실(대신 큼). 낮은 `Q2/Q3`는 많이 가볍지만 품질 저하 큼.

## 부가 접미사 (뒤에 더 붙는 것들)
많이 붙는 것들을 성격별로 묶었다. **순서는 제작자 마음**이라 뒤죽박죽 섞여 나오기도 한다.

### 🕒 버전·시점·컨텍스트
- **`-hf`** — HuggingFace `transformers` 포맷으로 변환됨(예: `Llama-2-7b-hf`). 실행 편의용 표기.
- **`-v0.1` / `-v0.2` / `-v3`** — **그 파인튜닝의 리비전**(모델 세대와 별개. 미세조정 버전).
- **`-128k` / `-32k` / `-1M`** — **컨텍스트 길이**(한 번에 넣을 수 있는 [[토큰]] 수).
- **`-2409` / `-0125`** 같은 숫자 — **날짜 스탬프**(YYMM 또는 MMDD, 릴리즈 시점).
- **`-latest`** — 항상 최신을 가리키는 별칭(고정 버전 아님).
- **`-preview` / `-exp`(experimental) / `-alpha` / `-beta` / `-rc`** — 정식 전 **시험판**.

### 🎚️ 크기·티어 이름 (파라미터 수 대신 등급으로)
- **`mini` / `nano` / `small` / `medium` / `large` / `xl`** — 숫자(B) 대신 **상대적 크기 등급**(예: `Phi-3-mini`, `GPT-4o-mini`).
- **`flash` / `pro` / `ultra` / `lite` / `turbo`** — 제작사가 붙이는 **속도·성능 등급**(예: Gemini `Flash`=빠름/싸다, `Pro`=고성능).
- **`-o`(omni)** — 텍스트·이미지·음성 통합 멀티모달(예: `GPT-4o`).
- **`E2B` / `E4B`**(Gemma 3n) — **E = effective(유효) 파라미터**. 실제 총 파라미터는 더 많지만 **선택적으로 일부만 켜서** 2B/4B급으로 돈다(온디바이스용). → [[온디바이스 모델 배포]]

### 🧪 정렬·학습 방법 (어떻게 다듬었나)
[[파인튜닝]]의 **어떤 기법**을 썼는지 표기.
- **`-SFT`** — 지도 미세조정(supervised). **`-CPT`** — 계속 사전학습.
- **`-DPO` / `-ORPO` / `-KTO` / `-RLHF` / `-GRPO`** — **선호 최적화·정렬** 기법들(사람이 선호하는 답으로 조정).
- **`-abliterated` / `-uncensored`** — 커뮤니티가 **거부 응답(refusal)을 제거**한 개조본. 원 제작사 공식본 아님.

### 🔀 모델 병합 (mergekit로 여러 모델 섞기)
- **`-slerp` / `-ties` / `-dare` / `-della` / `-merge`** — 여러 모델의 가중치를 **수학적으로 병합**한 방법 이름.
- **`-frankenmerge` / `-passthrough`** — 레이어를 이어붙여 크기를 키운 병합(예: 규격 밖 크기).
- 브랜드성 튠 이름도 붙는다: `-hermes` / `-openhermes` / `-dolphin` / `-nous` 등(특정 팀의 파인튜닝 시리즈).

### 🗜️ 양자화 심화 표기
5번 항목의 기본 위에 더 세밀한 표기들:
- **`-bnb-4bit`** — bitsandbytes 4비트(예: Unsloth `...-bnb-4bit`). **`-QAT`** — 양자화를 **학습 때부터 반영**(품질↑, 예: `gemma-3-...-qat-q4_0`).
- **`IQ`계열**(`IQ2_XXS`·`IQ3_M`·`IQ4_XS`) — **비선형 룩업 + imatrix 보정**을 쓰는 신형 저비트 GGUF. 같은 비트면 옛 방식보다 품질↑.
- **`imatrix` / `iMat` / `-i1`** — **importance matrix(중요도 행렬)**. 보정 데이터로 "**어떤 가중치가 더 중요한지**" 측정해 그쪽에 정밀도를 몰아줌 → 저비트 품질 개선.
- **`w4a16` / `w8a8`** — **가중치(w)·활성(a) 비트를 따로** 표기(w4a16 = 가중치 4비트 + 활성 16비트).
- **GPTQ 세부**: `-4bit-32g`(**32g = 그룹 크기 32**), `-actorder`/`-act-order`/`-desc_act`(정밀도 개선 옵션).
- **`-00001-of-00003`** — 파일이 커서 **여러 조각으로 분할**된 것(전부 받아야 함).

### 🖥️ 런타임·디바이스용 내보내기 포맷
어디서 돌릴지에 맞춰 변환한 형식:
- **`-ONNX`** — 범용 추론 런타임. **`-TensorRT` / `-trt` / `-trtllm`** — NVIDIA GPU 최적화.
- **`-OpenVINO`** — 인텔. **`-CoreML`** — 애플. **`-MLX`** — 애플 실리콘. **`-tflite`** — 모바일/엣지.

### 🎯 특수 목적·기타
- **`-Guard`** — 안전 필터 전용(예: `Llama-Guard` — 유해 입력/출력 분류). **`-tool-use` / `-function-calling`** — 도구 호출 특화.
- **`-chatml`** — 특정 **프롬프트 포맷**을 쓰도록 맞춤.
- **언어/도메인 태그** — `-ko`(한국어), `-multilingual`, `-medical`, `-finance` 등.

## 왜 중요한가
- **이름만으로 "쓸 수 있는 모델인지"를 즉시 판단**한다: 크기(내 VRAM에 뜨나) + 튜닝(대화용인가 base인가) + 양자화(얼마나 가벼운가/포맷이 내 실행기랑 맞나).
- 로컬 LLM([[로컬 LLM과 셀프호스팅]])·온디바이스([[온디바이스 모델 배포]])에서 모델 고를 때 **가장 먼저 보는 정보**. 잘못 받으면(예: base를 채팅용으로, GPTQ를 CPU로) 시간만 버린다.
